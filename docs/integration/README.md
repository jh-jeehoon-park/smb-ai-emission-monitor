## 2. 왜 붙였는가

`[사용자 요청 2026-08-27]` — *"제대로 설계가 완료된 DB가 아니며, 모든 페이지 데이터 통일, 데이터가 실시간으로 변화하는 것을 보고싶다는 대표님의 요청"*

붙이기 전의 화면은 **통일되어 있지 않았다.** 계측(`getMeasurementSeries`)과 이상 점수(`buildAnomalyScores`)가 서로 다른 시드의 난수였고, `demo-scenario.ts`의 상수를 공유할 뿐 **값이 서로를 설명하지 못했다.** 그리고 `DEMO_NOW_ISO`로 시각이 멈춰 있었다.

> **명세 PDF가 계약이고 이 문서는 구조다.** 엔드포인트·파라미터·응답 모양은 그쪽이 정본이며 여기서 반복하지 않는다.

## 3. 계층 — 고칠 자리를 한 곳에 모은다

명세 §7.3이 정한 넷을 그대로 따른다. 이 연동은 **임시 구조다**(명세 §1.2) — 프론트가 계측 서버를 직접 부르는 것은 백엔드가 없어서이고, 나중에 백엔드를 경유하게 될 때 고칠 자리가 한 곳이어야 한다.

| 무엇 | 어디 |
|---|---|
| 접속 계층 | `src/shared/api/thingsboard/` — 경로·오류 분류·재시도 |
| **자격증명·토큰** | `src/app/api/tb/[...path]/route.ts` — **서버 전용** |
| 장비 등록부 | `src/entities/measurement/api/device-registry.ts` — 사업장ID ↔ `deviceId` |
| 매퍼 | `src/entities/measurement/api/telemetry.mapper.ts` — **격자 채우기·결측 판정이 여기 있다** |
| 조회 훅 | `src/entities/measurement/api/use-site-series.ts` — 화면이 쓰는 것 |

컴포넌트는 `MeasurementPoint`만 본다. 서버 응답 모양(`TbTsValue`)이 컴포넌트까지 올라오면 문자열 `value`·유령 표본·격자 어긋남을 다루는 코드가 전 화면에 퍼진다.

### 3.1 왜 프록시를 두는가

브라우저가 계측 서버를 직접 부르지 않는다. 두 가지가 동시에 해결된다.

| 막는 것 | 프록시가 없으면 |
|---|---|
| 자격증명 노출 | `NEXT_PUBLIC_`으로 넘겨야 해 **번들에 실린다** |
| mixed content | 서버가 http라 https 배포본에서 **전부 차단된다**(명세 §2) |

토큰 획득·선제 갱신·재로그인(명세 §3.1)이 전부 이 한 파일에 있다. 브라우저는 토큰을 보지 않는다.

**통로를 열어 두지 않는다.** 자격증명을 붙여 주는 경로이므로 조회 다섯 개만 정규식 허용 목록으로 통과시킨다 — 열어 두면 개발 서버에 닿는 누구나 테넌트 전체를 쓴다.

## 4. 자격증명

`.env.local`에 두고 **`NEXT_PUBLIC_`을 붙이지 않는다.** 이름은 `.env.example`에 있고 값은 명세 PDF §2·§3에 있다.

```
TB_BASE_URL · TB_USERNAME · TB_PASSWORD
```

**셋을 비워 두면 계측 서버 모드가 꺼진다.** 오류가 아니라 폴백 신호다(§5).

### 4.1 한 번에 받을 수 있는 것은 25시간이다

| 사실 | 값 |
|---|---|
| 보유 기간 | **적어도 17.7일**(가장 오래된 표본 `2026-08-20T07:45Z`, 2026-09-07 실측) |
| 한 응답의 상한 | `TB_TIMESERIES_LIMIT` **1,500표본** — 넘으면 에러가 아니라 **조용히 잘린다**(명세 §4.4) |
| ⇒ 1회 조회의 최대 구간 | **25시간.** 24시간(1,440)은 들어가고 3일(4,320)은 못 들어간다 |

그래서 **하루가 조회의 단위다.** 24시간을 넘는 구간을 볼 일이 생기면 하루씩 나눠 받아 이어 붙인다 — 3일이면 3회다. **지금 그렇게 받는 화면은 없다**: 전 화면이 `HISTORY_WINDOW_HOURS`(24)를 쓴다.

`agg=AVG`로 서버에 접게 하지 않는 이유는 §6.1과 같다: 버킷 `ts`가 표본 시각이 아니라 **구간 중앙**으로 와서 격자에 얹히지 않는다(명세 §4.4).

**보유 기간을 «7일»로 적어 두었던 것은 틀렸다** `[사용자 확인 2026-09-07]`. 2026-09-01에 7일 창을 요청해 받은 8,883표본을 보유의 **상한**으로 읽었는데, 그것은 우리가 물은 구간의 길이였을 뿐이다. 30일을 물어 보니 **13,923표본이 오고 2026-08-20까지 거슬러 간다** — 그 날짜는 에뮬레이터가 쓰기 시작한 시점으로 보이며, **TTL은 여전히 모른다**(한 번의 관측으로는 «아직 지워지지 않았다»와 «지우지 않는다»를 가를 수 없다). 그래서 값이 아니라 **하한**으로 적는다.

### 4.2 주소는 다시 내부망이다 (2026-09-15)

| | |
|---|---|
| 지금 | **`http://192.168.50.25:28080`** — 사내망에서만 닿는다 |
| 한때 | `http://211.44.234.90:28080`(공인 IP 포트포워딩, 2026-09-01~) |

`[사용자 확인 2026-09-15]` — *"에뮬레이터 시작해놓긴 했는데 외부 IP로 접속이 안 되는 것 같아요. 일단 내부 IP로 사용하셔야 할 것 같습니다."* 공인 IP는 실제로 죽어 있었다: `tracert`가 `211.44.234.0/24`의 라우터까지 가서 **«대상 호스트에 연결할 수 없습니다»** 로 끊겼다(그 주소에 응답하는 장비가 없다는 뜻이다).

> **`:54300`이 아니라 `:28080`이다.** 사용자가 전달한 `192.168.50.25:54300`은 **ECP 에뮬레이터의 제어판**이고 ThingsBoard API가 아니다 — 그 패널의 `/api/state`가 `"tb":{"http":"http://192.168.50.25:28080"}`으로 스스로 알려 준다. 패널 주소로는 `/api/auth/login`이 404다.

**그래서 «배포본도 실측을 본다»가 다시 거짓이 됐다.** 2026-09-01에 공인 IP로 그 전제가 깨졌다고 적었는데(아래 §5 인용), 사내망 주소로 돌아오면서 **배포본은 다시 폴백으로 돈다.** 폴백을 남긴 판단이 두 번 다 맞았다 — 근거가 «구조적으로 못 닿는다» ↔ «실패는 일상이다» 사이를 오갔을 뿐이고, 어느 쪽이든 폴백이 필요하다.

> 계정이 명세 PDF에 평문으로 들어 있다. 이 저장소를 **private으로 유지해야 하는 이유가 하나 더 늘었다** — `docs/datasets`의 실측 데이터, `docs/applications`의 원문 PDF에 이어 셋째다.

## 5. 폴백 — fixture는 임시물이 아니다

**닿지 않으면 fixture로 돌아간다** `[사용자 결정 2026-08-27]`. 재기동·토큰 만료·네트워크 순단으로 실패가 일상이 된다(명세 §8) — 실패마다 화면이 비면 시연이 멈춘다.

> **«배포본에서는 아예 닿지 않는다»는 더는 사실이 아니다** `[사용자 확인 2026-09-01]`. 이 절은 한때 폴백의 근거를 *"계측 서버는 사설망 http라 배포본에서는 아예 닿지 않고"* 라 적었다 — 그때는 사설망 주소뿐이었다. **공인 IP로 포트포워딩되어**(`211.44.234.90:28080`) Vercel 함수에서 나가는 것까지 확인했고, 배포본도 실측을 본다.
>
> **그래도 폴백은 남는다.** 근거가 «구조적으로 못 닿는다»에서 «실패는 일상이다»로 바뀌었을 뿐이다 — 위 문장이 그것이다.

| `status` | 뜻 | 헤더 배지 | 화면 고지 띠 · 다시 시도 |
|---|---|---|---|
| `pending` | 아직 확인 전 | `수신 확인 중` | **없음** — 아직 묻지 않았다. 스켈레톤이 이미 말한다 |
| `live` | 계측 서버에서 받는 중 | `계측 서버 수신 중 · 1분 주기` | **없음** — 정상일 때 화면이 달라지면 요청하지 않은 변경이다(**A2**) |
| `live` + `unreceived` 있음 | 붙었는데 일부 계열이 한 점도 안 온다 | 같음 | `계측 N종이 서버에서 오지 않습니다` · **다시 시도 있음** |
| `fallback` + `unconfigured` | 계측 서버에 붙지 않음 | `내장 데이터` | **없음** — 오류가 아니다(아래 참조) |
| `fallback` + `unreachable` | 재시도까지 실패 | `내장 데이터 · 서버 미연결` | `계측 서버에 닿지 못해…` · **다시 시도 있음** |
| `fallback` + `unauthorized` | 갱신·재로그인까지 실패 | 같음 | `계측 서버 인증에 실패해…` · **다시 시도 있음** |
| `fallback` + `notFound` | 그 사업장만 장비 미등록 | 같음 | `이 사업장의 장비가…` · 다시 시도 **없음** |
| `fallback` + `badRequest` | 우리 코드 버그 | 같음 | `요청이 잘못되어…` · 다시 시도 **없음** |

### 5.2 배지는 어디서 왔나, 띠는 왜 그렇게 됐나 (2026-09-15)

`[사용자 결정 2026-09-15]` — **헤더 배지 하나로는 모자랐다.** 12px 우측 상단이라 차트를 읽는 사람 눈에 들어오지 않고, 무엇보다 **왜 그렇게 됐는지와 무엇을 할 수 있는지를 말하지 않는다.** 2026-09-15에 반나절 그 상태로 돌았다 — 공인 IP가 죽어 내장 데이터를 그리는 동안 패널은 값을 실제 값처럼 냈다.

그래서 **화면 제목 바로 아래 고지 띠**를 한 줄 둔다(`widgets/app-shell/ui/telemetry-notice.tsx`). 배지는 «어디서 왔나», 띠는 «왜 그렇게 됐고 무엇을 할 수 있나»다.

**`TbFailure` 넷을 각각 다르게 적는다.** `errors.ts` 첫 줄이 *"실패의 종류. 화면이 각각 다르게 보여야 한다"* 고 적고 5종을 갈랐는데, 화면은 `unconfigured` 하나만 따로 대우하고 나머지를 한 문구로 뭉치고 있었다. 문구의 단일 출처는 `shared/config/notices.ts`이고 `notices.test.ts`가 **넷이 서로 다른지** 값으로 센다.

**`unconfigured`에는 띠를 두지 않는다.** 접속 정보를 두지 않은 것은 오류가 아니라 폴백 신호이고, 사내망 주소로 돌아온 지금(§4.2) **배포본은 상시 이 상태다** — 띠가 늘 떠 있으면 화면 가구가 되어 진짜 두절이 그 안에 묻힌다.

**「다시 시도」가 무엇을 하는가** — 접두 키 `['telemetry']` 무효화 **+ 정착 기록 비우기**(`forgetSettled`). 둘째를 빠뜨리면 **버튼이 최악 94초 매달린다**: 첫 로드에만 2.5초 마감을 거는 근거가 *"배경 갱신은 아무도 기다리지 않는다"* 인데, 수동 재시도는 정확히 그 반대다. 한 번 붙었다 끊긴 사업장(가장 흔한 경우)은 이미 «정착»이라 마감을 못 받는다.

**`notFound`에 버튼을 두지 않은 이유가 따로 있다.** 장비 등록부(`device-registry.ts`)의 캐시가 세션 동안 비워지지 않아 **다시 눌러도 같은 답이 온다.** 버튼을 열려면 그 캐시를 비우는 일이 먼저다 — 순서를 뒤집으면 버튼이 거짓말을 한다.

**계측을 읽지 않는 화면에는 띠가 뜨지 않는다.** 설비·사업장 설정은 애초에 API가 없는 fixture라 «실패»가 성립하지 않는다 — 거기에 같은 표기를 붙이면 없는 장애를 주장하게 된다(**E4**). 셸에 띠를 한 번 두면 *"계측을 쓰지 않는 도메인은 저절로 빠진다"* 고 적었다가 **정반대임을 실측으로 잡았다**(셸은 모든 화면 위에 있다). 지금은 `NavItem.readsTelemetry` 표식이 정하고, `navigation.test.ts`가 **라우트의 위젯을 열어 실제 사용 여부와 대조한다.**

문구의 단일 출처는 `src/entities/measurement/config/constants.ts`의 `TELEMETRY_STATUS_LABELS`다. 화면마다 다시 적지 않는다 — 같은 상태가 다른 말로 보인다.

**`pending`과 `fallback`을 가르는 것이 요점이다.** 아직 모르는 것을 `서버 미연결`로 적으면 없는 사실을 주장하게 된다 — 결측을 0으로 그리지 않는 것과 같은 규약이다(**E4**).

**`unconfigured`를 실패로 적지 않는 것도 같은 이유다.** 접속 정보를 두지 않은 것은 오류가 아니고, 그 상태에 상시 경고를 띄우면 정작 진짜 두절일 때 눈에 띄지 않는다.

> **`frontend.rule.md` A1과 부딪힌다.** A1은 *"실 API 연동 시 Mock 전량 제거"*를 요구하는데 폴백이 fixture를 요구한다. **사용자 결정이 이긴다**(§5 레벨 1) — 다만 fixture의 지위가 바뀐다: *임시물*이 아니라 **서버 미도달 시의 정식 대체 원천**이다. 백엔드가 정식화되면 이 예외를 다시 판단한다 — **«배포본에서도 닿게 되면»이라는 조건은 2026-09-01에 이미 충족됐고**, 그럼에도 폴백은 남겼다(위 인용 참조). 다시 판단할 시점은 프론트가 계측 서버를 직접 부르지 않게 되는 때다(§3의 «임시 구조»).

### 5.1 계측 서버가 주는 값도 실측이 아니다

**ThingsBoard로 들어오는 값은 센서에서 온 것이 아니다** `[사용자 확인 2026-09-01]`. 주관사에게 받은 자료를 참고해 만든 **에뮬레이터 출력**이다.

이 사실이 문구를 바꿨다. 배지는 한때 서버 쪽을 `실측 수신 중`, 폴백을 `시연 데이터`라 적었는데 **그 대비가 거짓이었다** — 둘 다 생성값인데 한쪽만 «시연»이라 적으면 보는 사람이 다른 쪽을 관측으로 읽는다. 결측을 0으로 그리지 않는 것과 같은 종류의 거짓말이다(**E3**·**E4**).

그래서 배지는 **«진짜냐»가 아니라 «어디서 오느냐»로 가른다** `[사용자 결정 2026-09-01]`. 두 문구가 각자 출처만 말한다 — 계측 서버에서 왔는가, 앱에 내장된 값인가. 그 구분은 에뮬레이터라도 여전히 값어치가 있다: **갱신되는 값과 굳어 있는 값이 다르고**, 서버가 끊겼는지 아닌지를 화면이 말해야 한다.

| | |
|---|---|
| 여전히 참 | 헤더 `Demo` 뱃지 · 툴팁의 `시연용 생성 데이터 — 실제 계측값이 아닙니다`(`DEMO_NOTICE`). 오히려 예전보다 더 참이다 — 그때는 헤더가 같은 자리에서 `실측 수신 중`이라 적어 서로 어긋났다 |
| 바꾸지 않은 것 | 계측 등급 이름 `실측`·`AI 추정`·`계측 없음`(`PROVISIONAL_MEASUREMENT_GRADE_LABELS`)과 그 계열색(`--actual`·`--ai`). 그쪽은 **다른 축**이다 — 계측 채널로 받은 값인가 모델이 산출한 값인가를 가르며(**E3**), 원천이 에뮬레이터여도 그 구분은 그대로 성립한다 |

> **이 문서의 «실측»은 그 뜻이 아니다.** §8·§9에서 *"실측으로 확인한"* 이라 적은 곳은 **우리가 서버에 직접 붙어 재 본 것**을 말한다. 값의 성격이 아니라 확인 방법이다.

## 6. 반드시 지키는 셋

### 6.1 격자를 먼저 만들고 채운다

응답 배열을 순서대로 zip하면 밀린다 — **키마다 타임스탬프 집합이 다르다**(명세 §6.2). 안 채워진 칸이 곧 결측이라는 사실도 격자가 있어야 나온다.

### 6.2 값 0과 값 없음을 끝까지 가른다

`?? 0`을 쓰면 규약이 깨진다. 방지시설 미가동 구간의 전류 0은 **측정된 사실**이고(명세 §6.4), 통신 두절 구간의 빈칸은 모름이다. 둘을 같게 만들면 무단방류 의심 판정이 사라진다.

### 6.3 창 전체를 다시 받는다

꼬리만 이어 붙이지 않는다. 계측 장비가 로컬에 7일을 저장했다가 복구 시 **과거 시각 그대로** 올려 보내므로(명세 §6.3), 꼬리만 받으면 **한 번 빈 구간이 영원히 비어 있게 된다.**

## 7. 시각 — `Z`가 붙지만 UTC가 아니다

이 저장소의 시각 문자열은 **KST 벽시계 값에 `Z`가 붙은 것**이다(`shared/config/demo.ts`). 화면 포맷터가 UTC 게터로 읽기 때문이다.

실 epoch을 그대로 `toISOString()`하면 **9시간 어긋난 값에 KST 라벨**이 붙는다. 서버에서 온 시각은 반드시 `kstIsoFromEpoch()`(`shared/lib/format.ts`)를 지난다 — 관례를 지키는 자리를 한 곳에 모아 둔 것이다.

## 8. 채널 — 우리 24항목 vs 서버 26채널

**단위·측정범위·표시 자릿수가 13개 공통 항목에서 전부 일치한다**(명세 §5 대 `shared/config/measurement.ts`). 양쪽이 같은 원문 사양표(`[원문 p.55]`)를 따랐다.

| | |
|---|---|
| 서버가 주는데 우리 `SeriesCode`에 없는 것 | `discharging`(방류 플래그 — 계열이 아니라 값이다) |
| 우리에게 있는데 서버에 없는 것 | `vibration`(단위 미정 `[TBD-49]` — 애초에 `SeriesCode`가 아니다). **유입 수질 8종은 2026-09-15에 들어왔다** — 아래 §8.0 |
| **이름이 다른 것** | **열둘이다**(2026-09-15 전에는 둘) — 유출 수질 8종과 TN·TP가 `Out` 접미사를 얻었다(`pH` ← `pHOut`), 유량은 그대로 `inflow` ← `flowIn` · `flow` ← `flowOut`. 표는 `TB_CHANNEL_BY_CODE` 한 곳이다 |

### 8.0 유입 수질 8종 — 원천이 셋으로 갈라졌다

> **이 절의 전제는 2026-09-15에 깨졌다** `[사용자 확인 2026-09-15]`. 에뮬레이터가 **유입 수질 8종을 내기 시작했다** — `pHIn`·`DOIn`·`ECIn`·`turbidityIn`·`TOCIn`·`NO3NIn`·`temperatureIn`·`chromaticityIn`이 26채널 안에 있다. 그러면서 **유출 쪽 이름이 `Out`으로 갈렸고**, 그것이 §9 ④의 결함을 낳았다.
>
> **아직 갈래를 옮기지 않았다.** `DEMO_SERIES_CODES` → `RECEIVED_SERIES_CODES`로 옮기면 «시연값» 배지가 걷히고 `SCR-AD-005`의 처리 판정이 **역산값이 아니라 실측 두 지점**에서 나오는데, 그것은 그 화면이 말하는 바를 바꾼다(**A2**) — 사용자 결정 대기. 옮기기 전까지 화면은 지금처럼 **우리가 만든 값임을 배지로 밝힌다**(E3). 아래 서술은 그때까지의 근거로 남긴다.

**한때 계측 서버에 유입 수질 채널이 없었다** — 2026-09-10에 10개소 중 4곳을 다시 재 확인했고 16채널이 전부 같았다. 그런데 `SCR-AD-005`가 묻는 것이 **두 지점의 수질 차이**라(`[회의 2026-09-08]`) 그 여덟이 없으면 화면이 성립하지 않는다.

기존 두 갈래로는 담을 수 없었다 — `RECEIVED`에 넣으면 없는 키를 물어 **유령 표본**이 오고(명세 §7.1), `UNRECEIVED`에 넣으면 화면이 통째로 빈다. 그래서 **`DEMO_SERIES_CODES`** 를 셋째 갈래로 두었다.

| 갈래 | 뜻 | 화면 표기 |
|---|---|---|
| `RECEIVED_SERIES_CODES` | 계측 서버가 준다 | 값 그대로 |
| `UNRECEIVED_SERIES_CODES` | 서버에 채널이 없다 | `미수신` |
| **`DEMO_SERIES_CODES`** | **우리가 만든 시연값** — 유출 실측에서 `유입 = 유출 ÷ 잔존율`로 역산 | 값 + **`시연값` 배지** |

**불변식은 `RECEIVED ∪ UNRECEIVED ∪ DEMO === SERIES_CODES`** 이고 `telemetry.mapper.test.ts`가 값으로 잠근다 — 셋 중 어디에도 없는 계열은 매퍼가 손대지 않아 그 칸이 `undefined`로 남는데, 타입이 `number | null`이라 소비처가 `=== null`로 걸러도 통과한다.

**fixture와 실측이 같은 함수(`fillInletQuality`)를 지난다** — 두 경로에 식을 두 번 적으면 «내장 데이터로 볼 때와 서버로 볼 때 처리 판정이 다른» 화면이 된다.

> **채널이 오면 갈래만 옮긴다.** `DEMO_SERIES_CODES` → `RECEIVED_SERIES_CODES`로 옮기고 배지를 걷으면 구조는 그대로다. `[TBD-58]`(유입 유량)이 요청→신설로 해소된 선례가 있다. **그 채널이 2026-09-15에 왔다** — 옮기는 것은 위 인용의 이유로 대기 중이다.

**요청한 채널이 두 번 들어왔다.** 유입·유출이 2026-08-27에 `[TBD-58 해소]`, **방류 수조 수위(`level`)가 2026-09-07에** `[사용자 요청 2026-09-01]` → `[사용자 확인 2026-09-07]`. 그 사이(2026-09-01) 채널은 15종이었고 우리 계열 13개 중 수위 하나만 덮이지 않았다 — 지금은 **13개가 전부 서버로 덮인다.**

> **`[TBD-57]`이 해소된 것은 아니다.** 그 번호는 수위의 **단위·만수위·측정 지점**이 원문에 없다는 뜻이고, 채널이 왔다고 사양이 생기지는 않는다 — `PROVISIONAL_LEVEL_UNIT`·`PROVISIONAL_LEVEL_RANGE`가 그대로 맡는다.

### 8.1 TN·TP를 받는다 — 그러나 «계측»이라 적지 않는다

**2026-09-08에 합류했다** `[사용자 요청 2026-09-08]`. 그전까지는 서버에 채널이 있어도 **일부러 받지 않았다** `[사용자 확인 2026-09-07]` — 이 사업의 주된 목적이 그 둘을 AI로 예측하는 것이라, 계측 계열로 올리면 예측 대상이 계측값으로 둔갑한다는 이유였다.

**막는 자리가 바뀌었다.** 프로토타입에서는 **화면에 값이 그려지는 것이 1순위**이고 AI 소프트 센싱은 과제 성공 이후다 — 안 받으면 오염도 추정 화면이 시드 난수 생성값을 그리는데, 그쪽이 오히려 그것을 **`직접 계측`이라 적고 있었다**(**E3**). 받아 오는 편이 더 정직하다.

대신 **세 자리가 그 걱정을 대신 막는다.**

| 어디 | 무엇 |
|---|---|
| `ESTIMATE_SERIES_CODES` | `WATER_SERIES_CODES`와 따로 선다 — 계측 격자의 `수질 8종`과 시계열 필터에 오르지 않는다(**A2**). `DISCHARGE_SERIES_CODES`(수위)와 같은 선례 |
| `SeriesOrigin.preModel` | 화면이 **`계측 서버 수신 · AI 산출 예정`** 이라 적고 선을 파선으로 둔다. `직접 계측`은 없는 센서를, `소프트 센싱 추정`은 없는 AI 산출을 주장한다 |
| 검사 | `telemetry.mapper.test.ts`가 위 둘을 값으로 잠근다 |

**소프트 센싱이 붙으면 되돌린다** — TN·TP를 `softSensed`로 옮기고 `preModel`을 지운다.

우리 이름을 서버에 맞춰 바꾸지 않는다. 화면·문서·CSV가 전부 `inflow`·`flow`를 쓰고 있고, **서버 채널 이름이 화면 계약이 되면 저쪽이 바꿀 때마다 전 화면이 깨진다**(명세 §7.3이 경계한 그것이다). 잇는 일은 매퍼의 `TB_CHANNEL_BY_CODE` 한 곳이 한다.

**옛 `flow` 채널을 읽지 않는다.** 5분 주기였고 §9 ①의 결함으로 그 시각에만 옛 값이 남아 있었다 — **2026-09-07 실측에서는 키 목록에 아예 없다.** 그래도 `TB_CHANNEL_BY_CODE`의 매핑은 지우지 않는다: 이름이 우리 계열 `flow`와 같아, 매핑이 없으면 `channelOf`가 항등으로 떨어져 **없는 채널을 다시 묻게 된다**(유령 표본, 명세 §7.1).

**`discharging`이 채널로 온다.** 지금까지 시나리오로 파생하던 방류 여부를 서버가 직접 준다 — 방류 의심 판정이 오히려 강해진다.

**`DO`는 방류수 DO가 아니다** — 생물반응조 폭기조 DO이고 0.4 안팎이 정상이다(명세 §5.2). 화면이 어느 지점의 값인지 적어야 한다. **아직 적지 않았다** — 계측 서버 전환을 마칠 때 함께 처리한다.

## 9. 서버 쪽에 남은 결함 넷 — 실측으로 확인했다

**① 5분 데이터가 1분 구간과 섞여 있다.** — **두 번째다.**

```
S-08 discharging  5분 배수 시각(:00·:05…) 288개 중 방류 0 = 100%
                  그 밖 1,141개 중            방류 0 =   1%
```

5분 배수 시각에만 옛 값이 남아 있다. S-02·S-06의 `전류 0`(12개·4개)도 **100%가 그 시각**이다. 그대로 두면 방류 중단·미가동이 5분마다 깜빡이는 유령 구간이 되어 관내 감독의 방류 의심 판정이 오염된다. 우리 쪽은 1분 격자를 쓰므로 대부분 피하지만, **원천에서 지우는 편이 맞다.**

**같은 일이 2026-09-01에 다시 일어났다** `[사용자 확인 2026-09-07]`. 에뮬레이터가 5분으로 되돌아갔다가 **2026-09-07 09:40 KST에 다시 1분이 됐다**(10개소 전부 실측). 그 사이 6일치가 5분 간격으로 남아 있어, **되돌아온 직후 24시간 창은 1,440칸 중 20% 남짓만 찬다** — 창이 굴러가면서 저절로 메워진다. 지난번에는 백엔드가 24시간 전 구간을 1분으로 소급 백필해 기다릴 것도 없었다.

**그래도 격자를 5분으로 낮추지 않는다**(`COLLECTION_INTERVAL_MINUTES` 주석이 근거를 갖는다). 성긴 화면은 눈에 보이고 하루면 낫지만, 5분 격자가 섞인 옛 값만 골라 얹는 것은 **눈에 띄지 않는 틀린 값**이다 — 그래서 S-08이 24시간 내내 `방류 중단`으로 보였다.

**② 유입유량의 변동 폭이 비현실적이다.**

```
유입 35~1892 (50배)   유출 0~1000
중앙값은 유입 749 > 유출 646 로 방향은 맞다
그런데 유입 < 유출 역전이 사업장마다 26~42%
```

방향(평상시 유입이 조금 많다)은 맞지만 하한이 너무 낮아 역전이 상시로 일어난다. **방류 의심의 보조 근거로 쓸 수 없고**, 화면의 `나간 양이 더 많다` 표시가 계속 뜬다. 실제 공정에서 유입이 유출의 1/10로 떨어지는 일은 드물다.

**③ 수신이 몇 분씩 끊긴다.**

```
S-02 discharging  최근 6시간 325표본 (1분 주기면 360)
간격 분포          1분 315 · 4분 1 · 5분 8
3분 초과 간격      9건 / 324   가장 긴 간격 5분
```

주기는 1분이 맞는데 **4~5분짜리 구멍이 6시간에 아홉 번** 난다. 명세 §4.5가 비활성 기준을 `수집 주기 × 3`(=3분)으로 두므로 그 구멍은 **정의상 비활성**이고, 화면은 그동안 `모름`이라 적는다 — 규약대로다(E4).

> **2026-09-07 재측정은 아직 답이 되지 않는다.** 1분으로 되돌아온 직후 11분을 재 간격 11개가 전부 1.0분이었지만, «6시간에 아홉 번»을 가리려면 그만큼의 창이 필요하다. **해소로 적지 않는다** — 6시간이 쌓인 뒤 다시 잰다.

그런데 **종일 띄워 두는 화면에서는 40분에 한 번꼴로 `방류 중` ↔ `모름`이 깜빡인다.** 값이 틀린 것이 아니라 원천이 실제로 그 시간을 비운 것이라, 고칠 자리는 우리 쪽이 아니라 **에뮬레이터의 쓰기 주기**다.

> **S-09는 의도적으로 심은 것으로 보이며 잘 동작한다** — 24시간 내내 전류 0 · 전력 0 · 방류 1이라 무단방류 의심 사업장 그 자체다. S-08·S-10의 방류 중단도 원천 결함만 걷으면 쓸 수 있다.

**④ 채널 이름이 예고 없이 바뀐다.** `[사용자 확인 2026-09-15]`

에뮬레이터가 유입 계측을 내면서 **유출 채널 열 개에 `Out` 접미사를 붙였다.**

```
pH → pHOut · DO → DOOut · EC → ECOut · turbidity → turbidityOut
TOC → TOCOut · NO3N → NO3NOut · temperature → temperatureOut
chromaticity → chromaticityOut · TN → TNOut · TP → TPOut

그대로인 여섯   current · power · flowIn · flowOut · level · discharging
```

**없는 채널을 묻는 것은 에러가 아니다**(명세 §7.1) — 200이 오고 그 키만 빈 배열이다. 그래서 화면은 **헤더에 `계측 서버 수신 중`을 띄운 채 수질 8종과 TN·TP를 `수신 없음`으로 그렸다**: 이름이 그대로인 여섯이 실제로 오고 있어 접속 판정은 `live`였기 때문이다. 이 조합이 진단을 늦춘다 — 접속이 끊겼다면 배지가 `서버 미연결`이라 곧바로 보인다.

**우리 쪽 방어는 표와 검사다.** 이름을 잇는 일은 `TB_CHANNEL_BY_CODE` 한 곳에 있고, `telemetry.mapper.test.ts`가 «유출 수질은 `Out`을 쓰고 접미사 없는 옛 이름은 읽지 않는다»를 값으로 잠근다. **접미사 규칙(`code + 'Out'`)으로 만들지 않는다** — 예외가 여섯이고, 서버가 또 바꾸면 규칙이 **조용히 이름을 지어낸다.**

> **원천에서 알려 주는 것이 맞다.** 채널 이름은 계약이고 바뀌면 전 화면이 말없이 빈다. 다만 에뮬레이터라 예고를 기대하기 어려우므로(§5.1) **우리 쪽은 «틀리면 눈에 보이는» 구조로 둔다.**
