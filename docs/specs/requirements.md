## 2. 이 문서의 목적

원문이 요구한 기능([`functional-requirements.md`](../requirements/functional-requirements.md)의 FR-01~42)을 **산출물 양식(요구사항정의서 xlsx)에 맞춰 다시 정리**하고, 각각이 **어느 화면에서 어떻게 충족됐는지** 추적한다.

- 원문 FR 번호는 그대로 둔다. `REQ-*`는 양식용 ID이며 §3 추적표가 둘을 잇는다.
- ID 부여 규칙과 근거 표기 규약은 [`README.md`](README.md) §3·§4를 따른다.
- **미구현을 구현한 것처럼 쓰지 않는다.** 상태를 그대로 적는다.

### 2.1 구현 상태 값

| 값 | 뜻 |
|---|---|
| `구현` | 화면에서 확인 가능 |
| `부분` | 일부만 충족. 남은 것을 비고에 적는다 |
| `미구현` | 프론트 대상이지만 아직 화면이 없다 |
| `대상아님` | 프론트 화면의 몫이 아니다(Edge·서버·인프라·검증 절차). 사유를 비고에 적는다 |

### 발표자료 p.11 그림 기준 미표출 3건 — 착수 순서

그림이 규정한 기능 13종 중 화면에 없는 것이 3건이다. **데이터를 이미 가진 순서**로 붙인다 — 원문 확인을 기다리지 않아도 되는 것부터다.

| 순서 | 요구 | 왜 이 순서인가 | 선행 조건 |
|---|---|---|---|
| 1 | 수분석 실측 대비 검증 (REQ-AD-031) | **실측 데이터가 이미 저장소에 있다.** 항목(TOC·TN·TP)이 우리 추정 3종과 그대로 겹쳐 비교 화면을 바로 만들 수 있다 | 없음. 비교 주기 표기만 `[원문 p.38]` 월 2회와 성적서 실제(1일 8시점) 중 무엇을 쓸지 정하면 된다 |
| 2 | 유량(수량) 예측 (REQ-AD-010 확장) | 계측 `flow` 계열이 이미 있고 LSTM 구조가 수질과 같다. **막는 것은 데이터가 아니라 판단** — 유량이 예측 대상인지 입력 변수인지 `[INC-95]` | `[INC-95]` 확정. 대상이면 정확도 목표도 함께 정해야 한다(현재 목표는 "수질 예측 정확도"뿐) |
| 3 | ~~무단방류 의심 탐지~~ → **구현 완료 2026-08-19** | 원문 재독으로 방법(`[원문 발표 p.13]`)과 요구(`[원문 p.2]`)를 찾았다. 무단 판정 대신 **방지시설 미가동 방류 의심**으로 구현 | 남은 것은 임계값·체류시간 `[TBD-46]` |
