## 2. 이 문서가 있는 이유

`source-inconsistencies.md`는 **원문이 무엇을 말하지 않았는지**를 적는다. 이 문서는 그 공백을 **우리가 무엇으로 메웠는지**와 **그 메움이 타당한지**를 적는다.

`[PROVISIONAL]`·`[설계]` 표기가 코드와 화면 문서에 흩어져 있지만, 그것만으로는 **"이 추정이 얼마나 위험한가"** 를 한눈에 볼 수 없다. 심사나 인수인계에서 물어보는 것은 대개 그 질문이다.

### 2.1 적을 것과 적지 않을 것

| 적는다 | 적지 않는다 |
|---|---|
| 원문에 규칙이 없어 **우리가 만든 규칙** | 원문에 있는 값(그건 근거 표기로 충분하다) |
| 값 하나가 아니라 **판단**인 것 | 단순 표시 자릿수 같은 것(`provisional.ts`가 갖는다) |
| 틀렸을 때 **화면이 거짓을 말하게 되는** 것 | 틀려도 보기만 달라지는 것 |

### 2.2 위험도 기준

| 등급 | 뜻 |
|---|---|
| **높음** | 틀리면 화면이 **사실과 다른 판정**을 내놓는다 |
| 보통 | 틀리면 표시가 어긋나지만 판정 자체는 바뀌지 않는다 |
| 낮음 | 틀려도 보기 차이에 그친다 |

## 3. 추정 목록

### 3.1 알람 등급 ↔ 우선순위 대응 `INC-02`

| 항목 | 내용 |
|---|---|
| **무엇을 정했나** | 상태 등급 4단계를 알람 우선순위 3단계에 대응시켰다 — **위험·경고 → 긴급 · 주의 → 주의 · 정상 → 정보** |
| **원문은 어디까지 말하나** | 등급 4단계 `정상/주의/경고/위험` `[원문 발표 p.15·18]` · 우선순위 3단계 `긴급/주의/정보` `[원문 p.32]`. **둘의 대응 규칙은 없다** |
| **추정의 근거** | `[원문 발표 p.20 그림]`의 알람 목록이 **등급과 우선순위를 다른 열로** 보여주고, 그 예시가 `경고 → 높음` · `주의 → 중간`이다. 두 축이 별개이되 **단조 대응**임을 시사한다 |
| **왜 이 대응인가** | ① 그림의 두 예시(`경고→높음`·`주의→중간`)를 그대로 따른다 ② `위험`은 `경고`보다 높으므로 최소한 `경고`와 같은 최상위여야 한다 ③ `정상` 등급의 알람은 상태 악화가 아니라 사건 통지(예: 통신 두절 복구)이므로 `정보`가 맞다 |
| **적합성** | 그림의 두 쌍과 **어긋나지 않는다.** 4→3 축소이므로 어딘가는 합쳐져야 하고, 합칠 곳으로 최상위(`위험`·`경고`)를 택한 것이 **놓치는 쪽보다 안전하다** — 긴급을 주의로 낮추면 대응이 늦어진다 |
| **위험도** | **보통.** 우선순위는 **표시와 정렬**에만 쓰이고 값 자체를 바꾸지 않는다. 다만 알람 발송 채널이 우선순위로 갈리면(`[TBD-04]`) 위험도가 **높음**으로 오른다 |
| **철회 조건** | 주관기관이 대응 규칙을 확정하면 `entities/alarm/config/constants.ts`의 매핑 하나만 교체한다. 화면·테스트는 그 매핑을 참조하므로 따라온다 |

> **`위험 → 긴급`은 그림에 없는 쌍이다.** 그림이 보여준 것은 `경고`와 `주의`뿐이며, `위험`과 `정상`은 우리가 미뤄 넣었다.

### 3.2 설비 상태 이력을 만들어 낸 것 `REQ-AD-019`

| 항목 | 내용 |
|---|---|
| **무엇을 정했나** | 설비별 24시간 상태 격자(Heatmap)와 90일 잔여 수명 추이를 **없는 이력에서 만들어 냈다** |
| **원문은 어디까지 말하나** | `[원문 발표 p.18 그림]`이 **설비별 상태 Heatmap**(설비 × 00~24시, 4등급)과 **RUL 예측 그래프**(RUL(일) vs 경과일)를 화면 구성으로 요구한다. **값이 어떻게 쌓이는지는 없고**, 이력 저장소도 우리에게 없다(`REQ-AD-019` 미구현) |
| **추정의 근거** | 원문이 화면을 요구하므로 빈 화면으로 두면 요구를 못 채운다. 그래서 만들되 **이미 있는 축에서 파생**시켰다 — 결측은 `isMissingAt`, 방지시설 가동은 `isTreatmentIdleAt`이 이미 판정한 것을 시간 단위로 묶기만 한다 |
| **어긋나지 않게 한 장치** | ① 결측 시간은 `null`(모름)이고 등급으로 채우지 않는다(E4) ② 격자의 **마지막 칸은 현재 고장 확률 그대로**여서 카드·표와 같은 등급이 나온다 ③ RUL 추이의 **오늘 값은 카드의 값 그대로**다 ④ 잔여 수명은 **단조 감소**다 — 늘어나려면 정비가 있어야 하는데 정비 이력이 없다. 넷 다 테스트가 지킨다(`src/entities/equipment/history.test.ts`) |
| **적합성** | 화면 구성은 원문 그대로다. **값의 자취만 우리 것**이고, 화면에 "상태 이력 저장소가 없어 시연용으로 만든 값이다(REQ-AD-019)"를 적어 둔다 |
| **위험도** | **보통.** 등급 체계·현재 값은 기존 축을 그대로 쓰므로 판정이 새로 생기지 않는다. 다만 **과거 등급 분포**는 사실이 아니다 — 심사에서 "어제 오후에 경고였나"를 물으면 답할 수 없다 |
| **철회 조건** | 이력 저장소가 생기면 `entities/equipment/api/history.ts`의 두 생성 함수만 조회로 바꾼다. 타입(`EquipmentStatusCell`·`RulPoint`)과 화면은 그대로 쓴다 |

> **원문 예시의 `실제 고장 시점`은 그리지 않았다.** 시연 설비는 고장 난 적이 없고, 없는 사건을 표시하면 그 자리가 "여기서 고장났다"로 읽힌다(E3·E4).

### 3.3 잔여 수명이 0에 닿는 시점 `TBD-22`

| 항목 | 내용 |
|---|---|
| **무엇을 정했나** | 현재 잔여 수명을 감소 추세로 나눠 **0 도달 예상일**을 내고, 차트에 파선으로 그린다 |
| **원문은 어디까지 말하나** | RandomForest가 **고장 확률**과 **잔여 수명**을 낸다 `[원문 p.66]`. **언제 0이 되는지는 주지 않는다** |
| **추정의 근거** | `[원문 발표 p.18 그림]`이 RUL 곡선을 **우하향으로** 그리고 실제 고장 시점을 함께 찍는다 — 곡선이 바닥에 닿는 지점이 화면의 요지라는 뜻이다. 값 자체는 산술이다: `현재 RUL ÷ 일일 감소` |
| **어긋나지 않게 한 장치** | ① 지나온 값은 **실선**, 앞날은 **파선**으로 나눠 그린다 — 색만 다르면 인쇄·색각 이상에서 구분이 사라진다 ② 차트 바로 아래에 "**단순 외삽**이며 예지보전 모델의 산출이 아니다"를 적는다 ③ 툴팁도 두 값을 다른 이름(`지나온 값` / `추세 외삽`)으로 낸다 |
| **적합성** | 값이 아니라 **표시**를 더한 것이다. 원문이 주는 두 값에서 산술로만 나오며 새 판정을 만들지 않는다 |
| **위험도** | **보통.** 일일 감소 폭(`1 + 고장확률/100 × 0.9`)에 **원문 근거가 없다** — 폭이 달라지면 예상일이 달라진다. 다만 그 수가 정비 우선순위를 바꾸지는 않는다(순위는 MPI가 매긴다) |
| **철회 조건** | 모델이 잔여 수명의 시간 축을 직접 주면 `daysUntilDepleted`를 그 값으로 바꾼다. 감소 폭 상수 하나만 교체하면 추이·외삽·예상일이 함께 따라온다 |

## 4. 추정하지 않고 비워 둔 것

혼동을 막기 위해 함께 적는다. **아래는 추정하지 않았다** — 지어내면 화면이 없는 판정을 만들기 때문이다.

| 항목 | 왜 비웠나 |
|---|---|
| 배출허용기준 값 `[TBD-45]` | 지역구분·배출량 규모·방류 경로가 있어야 표를 고른다. pH 외에는 판정하지 않는다 |
| 무단 여부 판정 `[TBD-46]` | 신고 정보가 있어야 한다. `방지시설 미가동 중 방류 의심`까지만 적는다 |
| 조치 가이드의 산출 규칙 `[REQ-AD-021]` | 표 형식은 `[원문 발표 p.20]`에 있으나 **어떤 조건에 몇 %인지**가 없다 |
| 종합 위험도 `[TBD-47]` | 산출식·등급이 없다 |
| AI 모델 구조 `[INC-99·100·104]` | 모델이 미확정이다 `[사용자 확인 2026-08-19]` |

## 5. 갱신 규칙

- 새 추정을 도입하면 **같은 작업에서** §3에 행을 추가한다. 나중에 몰아 쓰면 근거를 잊는다
- 확정 답변이 오면 §3 행에 `[해소 YYYY-MM-DD]`를 적고 **지우지 않는다** — 무엇을 추정했었는지가 다음 사람에게 필요하다
- `[PROVISIONAL]` 값 중 **판단이 아닌 것**(자릿수·시연 구간 길이)은 여기 적지 않는다
