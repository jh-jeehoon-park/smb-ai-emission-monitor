### 2.1 권한

| 관리자 | 운영자 | 게스트 |
|---|---|---|
| R | R | R |

**관리자는 자사 1개소만 본다** `[회의 2026-08-13]` — **구현됨**. 라우트 가드가 URL에 `?site=자사&scope=site`를 박고, 주소를 직접 고쳐도 되돌린다. 범위를 URL에 두는 이유는 서버가 역할을 모르기 때문이다([README §4.4](../README.md)).

**사업장별 이상 점수 순위 블록은 관리자에게 보이지 않는다** `[설계: 이 블록의 존재 이유가 비교다 — "한 사업장만 보면 그 점수가 높은 건지 알 수 없다". 자사 1개소뿐인 관리자에게는 비교 대상이 없어 1행짜리 목록이 된다. 그 자리에 무엇을 둘지는 관리자 전용 화면 설계에서 정한다]`.

## 3. 화면 구성

```
┌────────────────────────────────────────┬──────────────────────────┐
│ 이상 점수 타임라인      [0-49 50-69 …] │ 이상 탐지 결과           │
│ ┌────────────────────────────────────┐ │  88  위험                │
│ │  면적 차트 + 4구간 밴드            │ │  ├──────────────┤       │
│ │  결측 구간 음영                    │ │  0  50  70  80  100     │
│ └────────────────────────────────────┘ │  산출 모델 / 대상 기간   │
├────────────────────────────────────────┤  산출 시각               │
│ 사업장별 이상 점수    점수 높은 순      │                          │
│ ┌────────────────────────────────────┐ │  주요 기여 변수 · XAI    │
│ │ 1 구미 염색 2공장  ∿∿∿   88 위험   │ │  TOC ▲ ────────  34%    │
│ │ 2 평택 도금 A라인  ∿∿∿   84 위험   │ │  DO  ▼ ─────     27%    │
│ │ …                                  │ ├──────────────────────────┤
│ │ 10 안동 식품 B동   ——  — 수신없음  │ │ 관련 알람                │
│ └────────────────────────────────────┘ │ (조건 = 이상 탐지)       │
└────────────────────────────────────────┴──────────────────────────┘
```

| 구성요소 | 형태 | 구현 |
|---|---|---|
| 이상 점수 타임라인 | 면적 차트, 4구간 밴드, 결측 음영, 구간 범례 | `anomaly-timeline/` |
| 사업장별 순위 | 행 목록, 상태 띠, 스파크라인, 점수·등급 | `anomaly-view.tsx` `SiteScoreRanking` |
| 이상 탐지 결과 | 게이지, 산출 메타, 기여 변수 막대 | `anomaly-panel/` |

### 4.5 방지시설 미가동 중 방류 의심 (`IdleDischargeRun[]`)

**이상 점수와 다른 축의 탐지다.** 점수가 낮아도 여기서 잡힌다 — 그래서 같은 화면에 나란히 둔다.

| 근거 | 내용 |
|---|---|
| 요구 | "방지시설 가동상태 및 설비 이상 판단 어려움"(Before) → **"방지시설 가동상태 자동 판단"**(After) `[원문 p.2]` |
| 방법 | "**전류 발생 시기와 유량 발생 시기를 비교** → 공정 체류시간을 고려한 데이터 매칭", "수질 변화와 유량·전류·전력 간 관계 분석하여 **방류 유무 판단 가능성 검토**" `[원문 발표 p.13]` |
| 기능명 | "무단방류 의심 탐지 — 패턴 분석을 통한 무단방류 탐지" `[원문 발표 p.11 그림]` |
| 데이터 | 진유원 6,528시간 중 **184시간(2.8%)이 유량=1·전류=0** `[데이터셋 Non_TMS_sites/04]` (전류계 위치=유입펌프) |

| 데이터 | 타입 | 단위 | 출처·근거 | UI 위치 |
|---|---|---|---|---|
| 구간 시작·종료 | ISO8601 | KST | `[파생: 방류=true ∧ 방지시설 미가동=true 인 연속 표본]` | 의심 구간 카드 제목 |
| 지속 표본 수 | number | 표본 | `[파생: 표본 수 × 수집 주기]` — 주기 5분은 `[원문 p.55]`. 화면은 시간으로 환산해 적는다 | 의심 구간 카드 `N시간 연속` |
| 그 시각 유량·전류·전력 | number \| null | m³/day · A · kW | `[원문 p.55]` 계측값 그대로. 전류·전력이 **0**인 것이 판정의 근거다 `[TBD-46]` | 의심 구간 카드 하단 3값 |
| 최소 지속 시간 | 12표본(1시간) | 표본 | `[PROVISIONAL]` **원문에 없다** `[TBD-46]`. 실증 데이터가 시간 단위 집계라 그보다 짧은 판정은 원본으로 검증할 수 없다 | 판정 근거 문단 |

**결측이면 구간이 끊긴다.** 방류 여부나 가동 여부 중 하나라도 수신되지 않았으면 그 표본에서 구간을 닫는다 — 모르는 시간을 이어 붙이면 없는 의심을 만든다(**E4**).

| 통신 두절 사업장 | 결과 패널이 `—` + "산출값 없음" + 마지막 수신 시각(**E3**) |
| 구간 결측 | 타임라인이 끊기고 해당 구간에 음영(**E4**) |
| 순위의 두절 사업장 | **점수를 0으로 내리지 않고** 목록 끝에 `수신 없음`(**E4**) |
| 관련 알람 0건 | 빈 목록. 개수를 머리글에 표기 |

## 7. 설계 근거

**"무단방류"라고 쓰지 않는다** `[설계: 무단 여부는 신고된 방류 시간대·유량 한도가 있어야 정해진다. 원문도 "방류 유무 판단 **가능성 검토**"까지만 말한다(발표 p.13). 저류된 물을 내보내는 중일 수도 있어, 판정이 아니라 의심으로 남기는 것이 옳다 — `README` §3.1은 법정 판정값을 지어내지 말라고 못박는다]`.

**판정과 그림이 한 원천에서 나온다** `[설계: 미가동 구간을 시나리오에 두고 계측 fixture가 그 구간의 전류·전력을 0으로 만든다. 두 곳에서 각각 정하면 이 화면은 "미가동"이라 적는데 시계열 차트에는 전류가 도는 모순이 생긴다]`.

**사업장별 순위를 넣은 이유** `[설계: 한 사업장만 보면 그 점수가 높은 건지 알 수 없다. 통합 관제의 판단은 늘 비교다]`. 대시보드에는 없던 요소다.

**구간 범례를 차트 머리글에 둔다** `[설계: 4구간 경계가 잠정값(TBD-02)이라 값을 읽는 사람이 경계를 함께 봐야 한다]`. 같은 범례를 통합 관제에서도 쓰며 구현은 한 곳이다(`anomaly-band-legend.tsx`) — 두 곳에 두면 구간이 갈린다.

**기여 변수에 방향(▲▼)을 함께 낸다** `[설계: 기여도만으로는 그 변수가 점수를 올렸는지 내렸는지 알 수 없다]`.

**색만으로 등급을 전달하지 않는다** — 색 + 글리프(●◆▲■) + 라벨을 함께 쓴다(REQ-NF-008).
