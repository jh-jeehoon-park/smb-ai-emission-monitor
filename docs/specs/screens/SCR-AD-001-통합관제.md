## 4. 요구 데이터

### 4.1 사업장 (`Site` × 10)

| 데이터 | 타입 | 단위 | 근거 |
|---|---|---|---|
| `id` `name` | string | — | `[설계]` 식별자·표시명 |
| `industry` | 5종 열거 | — | 섬유·염색/식품/화학/도금/전자부품 `[원문 p.37]` |
| `region` `address` `province` | string | — | `[PROVISIONAL]` 실증지 주소가 원문에 없어 시·군까지만 |
| `coordinates` | `[lat, lng]` | 도(°) | `[PROVISIONAL]` 주소 기준 시·군 중심 근사값. **주소와 함께 갱신해야 한다** |
| `anomalyScore` | number \| null | 점 | 0~100 정규화 `[원문 p.64]`. 통신 두절 시 `null` |
| `status` | 4등급 \| null | — | `[INC-01·03·04]` 잠정 4단계 |

| `lastSyncIso` | ISO8601 | KST | `[설계]` 마지막 수신 시각 |
| `spark` | (number\|null)[] | 점 | `[파생: 이상 점수 계열 다운샘플]` |

| `uptime` | number | % | 목표 ≥95% `[원문 p.38·119]` |

### 4.2 계측 (`MeasurementPoint` × 288)

수질 8항목(pH·EC·탁도·DO·수온·색도·NO₃-N·TOC) + 설비 3항목(전류·전력·유량). 단위·측정범위·정확도는 `[원문 p.55]`, 표시 자릿수는 `[PROVISIONAL]`.

- 5분 주기 × 24시간 = 288 표본. 수집 주기 1~10분 `[원문 p.30·48]` 범위 안 `[PROVISIONAL: 5분 고정]`
- **결측은 `null`.** 0으로 채우면 배출량 급감으로 오독된다(**E4**)

### 4.3 이상 점수 (`AnomalySummary` · `AnomalyPoint[]`)

| 데이터 | 타입 | 근거 |
|---|---|---|
| `score` | number \| null | 0~100 정규화 `[원문 p.64]` |
| `level` | 4등급 \| null | `[INC-01·03·04]` · 구간 경계 `[TBD-02]` |
| `computedAtIso` `windowLabel` `modelLabel` | string | **E3 — 산출 시각·대상 기간·모델을 값과 함께** |
| `contributions[]` | `{label, weight, direction}` | Feature Attribution `[원문 p.64]` |

### 4.4 예측 (`ForecastSummary`)

TOC 향후 6시간 `[원문 p.32·65]`. 상세는 [SCR-AD-004](SCR-AD-004-오염도추정.md) §4.

경향 카드 3개(TOC·TN·TP)에 **값·단위·경향·R²** 를 함께 낸다.

| 데이터 | 표시 | 근거 |
|---|---|---|
| 경향 값 | 항목별 자릿수 (TOC·TN 1 · TP 2) | `[PROVISIONAL]` `/prediction`과 같은 출처를 쓴다(**E1**) |
| R² | TN `0.886` · TP `0.782` · **TOC `원문 미규정`** | `[원문 p.27]` · TOC는 원문에 없다 `[INC-20·21]` |

**두 화면이 같은 포맷터를 쓴다** `[설계: 자릿수·문구를 각자 들고 있으면 통합 관제와 오염도 추정이 같은 값을 다르게 보여 준다]` — [`entities/prediction/lib/format-r2.ts`](../../../src/entities/prediction/lib/format-r2.ts).

### 4.5 알람 (`Alarm[]`)

우선순위 3종 `[원문 p.32]` · 조건 4종 · 상태 3종. 상세는 [SCR-AD-007](SCR-AD-007-알람이력.md) §4.

### 4.6 설비 (`Equipment[]` × 4)

고장 확률 0~100% `[원문 p.66]` · RUL · MPI `[TBD-22]`. 상세는 [SCR-AD-005](SCR-AD-005-설비예지보전.md) §4.

## 7. 설계 근거

**지도를 좌측 sticky 레일에 둔다** `[설계: 상세를 스크롤하는 동안에도 전체 위치가 보여야 관제 화면이다]`. 1280px 미만에서는 레일을 만들지 않는다 — 1024px에서 나누면 오른쪽에 210px만 남아 지표 타일이 44px로 뭉개진다(실측).

**지도 높이를 뷰포트에서 뺀다** `[설계: 폭 기준 분기만 쓰면 화면이 낮은 모니터에서 패널이 잘린다 — 1366×768에서 219px 잘림 실측]`. sticky 레일은 화면을 넘으면 아래쪽에 영영 닿을 수 없다.

**시도 확대는 자유 배율이 아니다** `[설계: 10개소 중 7개소가 서로의 클릭 영역을 침범. 안동 두 곳은 6.1px 거리에 핀 지름이 11px]`. 배율은 시도 bbox에서 계산해 1.4~3배이며, 상한 3배는 단순화한 지형이 각져 보이기 시작하는 지점이다.

**사업장이 있는 시도만 색칠한다** `[설계: 17개를 균일하게 칠하면 데이터가 없는 지역까지 무언가 있는 것처럼 읽힌다]`. 한 시도에 여럿이면 **가장 나쁜 등급**으로 칠한다 — 평균을 내면 위험이 묻힌다.

**지표 타일은 사업장별 값이다** `[설계: 하드코딩하면 사업장을 바꿔도 그대로라 조용히 거짓말을 한다]`.

기각한 대안: **타일 지도(Leaflet + CARTO)** — 출처 표기가 법적 의무라 화면에서 지울 수 없고, 한국어 지명 변형이 없어 `SEOUL`·`DAEGU`로 나온다. 외부 네트워크에도 의존한다. 상세는 [design-system §2.1](../../../design-system/smb-ai-emission-monitor/pages/dashboard.md).

색·타이포·지도 시각 결정은 [design-system 문서](../../../design-system/smb-ai-emission-monitor/pages/dashboard.md)가 검증기 결과와 함께 갖고 있다. 여기서 복제하지 않는다.
