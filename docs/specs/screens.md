## 2. 이 문서의 목적

**한 행이 한 화면이다.** 화면설계서 xlsx의 각 역할 시트로 그대로 옮겨진다.

행에 담기지 않는 근거(레이아웃·데이터·상호작용·설계 이유)는 [`screens/`](screens/) 아래 화면별 문서가 갖는다.

현재 구현된 화면은 **관리자 8종**이다. 운영자·게스트 화면은 구현 전이므로 여기에 적지 않는다 — [`requirements.md`](requirements.md) §6·§7에 미구현 상태로만 남아 있다.

## 3. 메뉴 구조

사이드바는 **2단 메뉴가 없는 평면 구조**다 `[설계: 화면이 8개뿐이라 그룹을 만들면 한 번 더 눌러야 하는 비용만 생긴다]`. 따라서 화면설계서의 `메뉴명(2Depth)` 열은 전부 `—`다.

```
AI 기반 지능형 배출관리 플랫폼   [원문 p.37·p.118]
├── 통합 관제          /
├── 이상 탐지          /anomaly
├── 시계열 변화        /timeseries
├── 오염도 추정        /prediction
├── 설비 예지보전      /equipment
├── 운영 최적화        /optimization
├── 알람 이력          /alarms      (미확인 건수 배지)
└── 리포트             /reports
```

메뉴 라벨과 화면 제목은 [`src/widgets/app-shell/config/navigation.ts`](../../src/widgets/app-shell/config/navigation.ts) **한 곳에서만** 정의된다 `[설계: 두 군데서 정의하면 라벨이 갈린다]`.

## 5. 권한 매트릭스 (CRUD)

원문이 규정한 권한은 **한 줄씩**이다 `[원문 p.69]`.

| 역할 | 원문 규정 |
|---|---|
| 관리자 | 모든 기능 접근 |
| 운영자 | 모니터링, 알람 확인 |
| 게스트 | 조회만 가능 |

이 세 줄에서 아래 매트릭스가 나온다. **원문이 화면 단위 권한을 규정하지 않았으므로 운영자·게스트 열은 해석이다** `[TBD]`.

| 화면 ID | 화면 | 관리자 | 운영자 | 게스트 | 근거 |
|---|---|---|---|---|---|
| SCR-AD-001 | 통합 관제 | R | R | R | 모니터링 `[원문 p.69]` |
| SCR-AD-002 | 이상 탐지 | R | R | R | 모니터링 |
| SCR-AD-003 | 시계열 변화 | R | R | R | 모니터링 |
| SCR-AD-004 | 오염도 추정 | R | R | R | 모니터링 |
| SCR-AD-005 | 설비 예지보전 | R | R | R | 모니터링 |
| SCR-AD-006 | 운영 최적화 | R | **?** | R | **운영 제안이 '모니터링'인지 원문이 답하지 않는다** `[TBD]` |
| SCR-AD-007 | 알람 이력 | R·U | R·U | R | '알람 확인' `[원문 p.69]`. 확인이 상태 전이까지인지 `[TBD]` |
| SCR-AD-008 | 리포트 | R·**D** | R | R | 내보내기(Download)를 D로 본다 `[설계]` |

- `C` 생성 · `R` 조회 · `U` 수정 · `D` 내보내기/삭제
- 현재 구현은 **관리자 열만** 동작한다. 운영자·게스트 화면은 미구현이며, 지금의 역할 표시는 **인가가 아니라 시연 표시**다(**E6 예외**).

> **확정 필요:** SCR-AD-006의 운영자 권한, SCR-AD-007의 '확인' 범위. 두 값 모두 원문에 없다 — 운영자 화면 구현 직전에 확인한다.

## 6. 화면 구분 — 통제 어휘

화면설계서 `화면 구분` 열에 쓰는 값이다. 새 값이 필요하면 여기 먼저 추가한다 `[설계: 같은 성격의 화면이 서로 다른 이름으로 불리면 목록이 분류 기능을 잃는다]`.

| 값 | 뜻 | 해당 화면 |
|---|---|---|
| 대시보드 | 여러 도메인을 한 화면에 모아 훑는 화면 | SCR-AD-001·002·006 |
| 차트 | 시계열·예측 그래프가 주가 되는 화면 | SCR-AD-004 |
| 차트·목록 | 그래프와 표를 함께 두는 화면 | SCR-AD-003 |
| 목록 | 표·행 목록이 주가 되는 화면 | SCR-AD-005·007·008 |
| 지도 | 지도가 주가 되는 화면 | (없음 — 지도는 SCR-AD-001의 구성요소) |
| 입력폼 | 값을 입력·제출하는 화면 | (없음 — 서버가 없어 제출 대상이 없다) |

## 8. 전 화면 공통 사항

화면별 문서에서 반복하지 않는다. 근거는 [`README.md`](README.md) §6에 있다.

| 항목 | 내용 |
|---|---|
| 셸 | 사이드바 + 헤더 + 본문. 사업장 선택은 헤더에 있어 전 화면에서 바뀐다 |
| URL 상태 | 사업장·기간·항목 필터가 쿼리에 남는다(P6) |
| 테마 | 라이트·다크. 두 팔레트 모두 WCAG AA 충족 |
| 시각 표기 | KST 명시, 수집 주기·조회 기간 병기(E5) |
| 결측 | `null`을 0으로 채우지 않고 끊어 표현(E4) |
| AI 산출값 | 산출 시각·대상 기간·모델 병기(E3) |
| 접근성 | 색+라벨+형태 병기, 본문 대비 4.5:1 이상, 키보드 이동 가능 |
| 반응형 | 1280px 이상 2단, 그 아래 단일 열. 390px에서 가로 스크롤 없음 |
| 모션 | 진입 시 1회. `prefers-reduced-motion`을 존중한다 |
| Figma node-id | **미보유.** Figma 파일이 없어 화면설계서의 해당 열은 공란이다 |
