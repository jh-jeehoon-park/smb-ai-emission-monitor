## 2. 이 문서의 목적

**한 행이 한 화면이다.** 화면설계서 xlsx의 각 역할 시트로 그대로 옮겨진다.

행에 담기지 않는 근거(레이아웃·데이터·상호작용·설계 이유)는 [`screens/`](screens/) 아래 화면별 문서가 갖는다.

현재 구현된 화면은 **운영자 8종**이다 `[회의 2026-08-13]`. 관리자 화면은 §4.2에 1종(비용 절감 현황), 공통 화면은 §4.1에 1종(로그인)이 있다. 게스트 전용 화면은 없다.

## 3. 메뉴 구조

사이드바는 **2단 메뉴가 없는 평면 구조**다. 항목은 9개이고 역할에 따라 보이는 것이 다르다 `[설계: 화면이 8개뿐이라 그룹을 만들면 한 번 더 눌러야 하는 비용만 생긴다]`. 따라서 화면설계서의 `메뉴명(2Depth)` 열은 전부 `—`다.

```
AI 기반 지능형 배출관리 플랫폼   [원문 p.37·p.118]
├── 비용 절감 현황     /cost-savings  (관리자에게만 보인다)
├── 수처리 공정        /process       (관리자에게만 보인다 · 운영자는 링크로 진입)
├── 통합 관제          /
├── 이상 탐지          /anomaly
├── 시계열 변화        /timeseries
├── 오염도 추정        /prediction
├── 설비 예지보전      /equipment
├── 운영 최적화        /optimization
├── 알람 이력          /alarms      (미확인 건수 배지)
└── 리포트             /reports
```

메뉴 라벨과 화면 제목은 [`src/widgets/app-shell/config/navigation.ts`](../../src/widgets/app-shell/config/navigation.ts) **한 곳에서만** 정의된다 `[설계: 두 군데서 정의하면 라벨이 갈린다]`.

## 5. 권한 매트릭스 (CRUD)

원문이 규정한 권한은 **한 줄씩**이다 `[원문 p.69]`.

| 역할 | 원문 규정 |
|---|---|
| 관리자 | 모든 기능 접근 |
| 운영자 | 모니터링, 알람 확인 |
| 게스트 | 조회만 가능 |

원문은 화면 단위 권한을 규정하지 않았고 `[TBD-07: 역할별 권한 매트릭스 상세]`, 사업장 단위 접근 범위도 없다 `[TBD-08]`. **회의가 역할의 범위를 정했다** `[회의 2026-08-13]`.

| 역할 | 범위 | 근거 |
|---|---|---|
| 운영자 | **전 사업장** 통합 관제 | `[회의 2026-08-13]` |
| 관리자 | **자사 1개소** + 설비 제어·시스템 설정 | `[회의 2026-08-13]` |
| 게스트 | 추측(B2G 감독기관 · 전 사업장 조회) | `[원문 p.69]` + `[설계]` |

- **범위를 URL에 두는 것은 취향이 아니라 제약이다.** 서버는 역할을 모르므로(첫 페인트 전 `data-role`로만 들어온다) 역할로 행 수를 가르면 하이드레이션이 깨진다. 행 수가 달라지는 필터는 전부 `scope` 쿼리를 거친다 — [`shared/config/scope.ts`](../../src/shared/config/scope.ts)
- **관리자 계정 2종**이 각각 다른 사업장을 갖는다(README §4.4). 계정↔사업장 매핑은 `[TBD-08]`이며 시연값이다
- **남은 것** — 관리자에게 숨긴 자리가 비어 있다(순위 블록 자리). 목적에 맞는 관리자 전용 화면은 별도 작업이다. **게스트 조작 차단도 미구현**이다.
- 지금의 역할 표시는 **인가가 아니라 시연 표시**다(**E6 예외**). 서버가 없어 클라이언트 분기일 뿐이다.

> **확정 경위:** SCR-OP-006의 운영자 권한과 SCR-OP-007의 '확인' 범위는 원문에 없어 [명확화 기록](../logs-clarifications/2026-08-13_역할별-화면-권한.md)으로 정했다. SCR-OP-006은 `[INC-94]`(p.69 ↔ p.50)가 열려 있어 발주처 확인이 남는다.

## 6. 화면 구분 — 통제 어휘

화면설계서 `화면 구분` 열에 쓰는 값이다. 새 값이 필요하면 여기 먼저 추가한다 `[설계: 같은 성격의 화면이 서로 다른 이름으로 불리면 목록이 분류 기능을 잃는다]`.

| 값 | 뜻 | 해당 화면 |
|---|---|---|
| 대시보드 | 여러 도메인을 한 화면에 모아 훑는 화면 | SCR-OP-001·002·006 · SCR-AD-001 |

## 8. 전 화면 공통 사항

화면별 문서에서 반복하지 않는다. 근거는 [`README.md`](README.md) §6에 있다.

| 항목 | 내용 |
|---|---|
| 셸 | 사이드바 + 헤더 + 본문. 사업장 선택은 헤더에 있어 전 화면에서 바뀐다 |
| URL 상태 | 사업장·기간·항목 필터가 쿼리에 남는다(P6) |
| 테마 | 라이트·다크. 두 팔레트 모두 WCAG AA 충족 |
| 시각 표기 | KST 명시, 수집 주기·조회 기간 병기(E5) |
| 결측 | `null`을 0으로 채우지 않고 끊어 표현(E4) |
| AI 산출값 | 산출 시각·대상 기간·모델 병기(E3) |
| 접근성 | 색+라벨+형태 병기, 본문 대비 4.5:1 이상, 키보드 이동 가능 |
| 반응형 | 1280px 이상 2단, 그 아래 단일 열. 390px에서 가로 스크롤 없음 |
| 모션 | 진입 시 1회. `prefers-reduced-motion`을 존중한다 |
| Figma node-id | **미보유.** Figma 파일이 없어 화면설계서의 해당 열은 공란이다 |
