## 2. 전체 구조

### 2.1 계층 구성 (원문 표기 그대로)

사업계획서는 시스템을 "Sensor Layer – Edge Layer – Cloud AI Layer – Application Layer로 구성된 3-Tier 아키텍처"로 규정한다. (사업계획서 p.48)

| 계층(원문 표기) | 역할 한 줄 요약(원문 표기) | 출처 |
|---|---|---|
| ① Sensor Layer (센서 계층) | 원시 데이터(raw data) 생성 / AI 분석을 위한 입력 데이터 제공 | 사업계획서 p.48 |
| ② Edge Layer (엣지 컴퓨팅 계층) | 실시간 대응(이상 발생 즉시 알람) / 데이터 압축 및 클라우드 전송 최적화 | 사업계획서 p.48, p.49 |
| ③ Cloud AI Layer (클라우드 AI 계층) | 예측·최적화·장기 분석 / AI 모델 고도화 및 재배포 | 사업계획서 p.49 |
| ④ Application Layer (운영 및 사용자 인터페이스) | 데이터 → 인사이트 → 행동(Action) 연결 | 사업계획서 p.50 |

- 각 계층은 기능적으로 분리되어 있으면서도 실시간 데이터 흐름을 기반으로 유기적으로 연계되는 구조를 가진다. (사업계획서 p.48)
- 발표자료는 동일 시스템의 아키텍처를 "Edge-NPU + Cloud-GPU 기반 Hybrid AI 구조"로 표기한다. (발표자료 p.21)
- 사업계획서는 Edge–Cloud 협업 구조를 "Hybrid AI"로도 표기한다. (사업계획서 p.49)

⚠ **모순** — 계층 구성이 원문 간 다르게 기술된다.

| 출처 | 기술 내용 |
|---|---|
| 사업계획서 p.48 | Sensor / Edge / Cloud AI / Application 4개 계층을 나열하면서 "3-Tier 아키텍처"로 표기 |
| 사업계획서 p.30 | "클라우드 기반 AI 분석 플랫폼(3-Tier 아키텍처)"의 구성을 Edge Layer / Cloud Layer / Application Layer 3개로 기술(Sensor Layer 없음) |

→ 상세는 [source-inconsistencies.md](../requirements/source-inconsistencies.md) 참조.

### 2.2 소프트웨어 3-Tier 구성 (사업계획서 p.30 기준)

| 계층 | 구성 요소 | 출처 |
|---|---|---|
| Edge Layer | IoT 게이트웨이, 로컬 데이터 전처리, NPU 기반 실시간 추론 | 사업계획서 p.30 |
| Cloud Layer | AI 모델 서버, 데이터베이스, API 서버, GPU 기반 재학습 | 사업계획서 p.30 |
| Application Layer | 웹/모바일 모니터링 대시보드 | 사업계획서 p.30 |

### 2.3 데이터 흐름 (Closed-loop)

- 통합 데이터 흐름: Sensor Layer → Edge Layer → Cloud AI Layer → Application Layer. (사업계획서 p.50)

| 계층 | 데이터 흐름상 역할(원문 표기) | 출처 |
|---|---|---|
| Sensor | 데이터 생성 | 사업계획서 p.50 |
| Edge | 실시간 처리 및 1차 판단 | 사업계획서 p.50 |
| Cloud | AI 분석 및 예측 | 사업계획서 p.50 |
| Application | 시각화 및 의사결정 | 사업계획서 p.50 |

- 폐쇄 루프(Closed-loop) 운영 구조: "데이터 수집 → 분석 → 추청 → 제어" (원문 표기 그대로. "추정"의 오기로 보이나 원문대로 옮김). (사업계획서 p.50)
- 발표자료는 동일 흐름을 "데이터 → 인사이트 → 의사결정"의 연계형 AI 분석 흐름으로 표기하며, "검증된 결과만 다음 단계로 전달"하는 연계형 AI 신뢰성 검증 체계를 둔다고 기술한다. (발표자료 p.20)

### 2.4 실시간 처리 파이프라인 5단계

| 단계 | 처리 내용 | 출처 |
|---|---|---|
| Step 1 | 다항목 수질센서로 pH, DO, EC, 탁도, 수온, TOC, NO3-N 등 주요 수질 항목을 1분 단위로 주기적 측정 | 사업계획서 p.68 |
| Step 2 | 엣지 컴퓨팅 장치(ECP)로 데이터 수집, 노이즈 제거 및 결측치 보정 등 전처리 수행 | 사업계획서 p.68 |
| Step 3 | 전처리된 데이터를 MQTT 기반 통신으로 클라우드 서버에 실시간 전송 | 사업계획서 p.68 |
| Step 4 | AI 분석 서버에서 AutoEncoder 이상 점수 산정, LSTM 기반 TOC·TN·TP 예측, RandomForest 설비 상태 분석, XMARL-PPO 강화학습 기반 설비 운전·에너지 최적화 분석 수행 | 사업계획서 p.68 |
| Step 5 | 설정된 임계값 초과 시 SMS, 이메일, 모바일 푸시 등으로 자동 알람 발송 | 사업계획서 p.68 |

## 3. Sensor Layer

현장 폐수처리 공정에서 발생하는 수질 및 설비 데이터를 실시간 계측하는 계층으로, 시스템의 입력 데이터 품질을 결정하는 핵심 영역이다. (사업계획서 p.48)

### 3.1 구성 항목 — 수질 센서

사업계획서 p.48은 "pH, DO, EC, 탁도, 수온, 색도, TOC, NO3-N 등 (12개 항목)"으로 기술하고, p.55는 수질 센서를 8개 항목으로 확정 표기한다.

| 센서 | 정확도 | 측정 범위 | 측정 원리 | 출처 |
|---|---|---|---|---|
| pH | ±0.1 | 0~14 | 유리전극식 | 사업계획서 p.55, p.29 |
| EC | ±2% | 0~20,000 μS/cm | 전도도식 | 사업계획서 p.55, p.29 |
| 탁도 | ±5% | 0~4,000 NTU | 광산란식 (90°) | 사업계획서 p.55, p.29 |
| DO | ±0.2 mg/L | 0~20 mg/L | 광학식 (형광) | 사업계획서 p.55, p.29 |
| 수온 | ±0.5°C | 0~50°C | 백금 저항 (Pt100) | 사업계획서 p.55, p.29 |
| 색도 | ±10 Pt-Co | 0~500 Pt-Co | 광투과식 (420nm) | 사업계획서 p.55, p.29 |
| NO3-N | ±5% | 0~100 mg/L | 광학식 방식 | 사업계획서 p.55 |
| TOC | ±10% | 0~500 mg/L | 광학식 방식 | 사업계획서 p.55 |

- TOC·NO3-N에 대해 p.29는 "UV흡광/분광 기반 광학식 분석, 정확도 ±5 이내"로 별도 표기한다. (사업계획서 p.29)
- 센서는 복합 센서 모듈 형태로 통합 구성된다. (사업계획서 p.48)

⚠ **모순** — 수질 측정 항목 수.

| 출처 | 기술 내용 |
|---|---|
| 사업계획서 p.17 | "간접 센서 기반 수질 측정 … 다항목 센서(**12개**) + 4가지 AI모델" |
| 사업계획서 p.23 | "다항목 센서(**8개**) + 4가지 핵심 AI모델 융합 구조 … 8개 항목 동시 측정 + 대체지표 기반 오염도 추정" |
| 사업계획서 p.48 | "pH, DO, EC, 탁도, 수온, 색도, TOC, NO3-N 등 (**12개 항목**)" — 8개만 나열하고 12개라 명시 |
| 사업계획서 p.51 | "대체 관리지표 기반 오염도 AI 추정 + **8개 센서**" |
| 사업계획서 p.55 | "①수질 센서(**8개 항목**)" |
| 사업계획서 p.59 | "pH, EC, 탁도, DO, 수온, TOC, TN, TP 등 **8개 이상** 항목이 동시 변화" — 색도·NO3-N 대신 TN·TP가 등장해 구성이 다름 |
| 사업계획서 p.62 | "TOC, TN, TP, pH, DO, SS, EC, 탁도, 유량, 설비 전류·전력 등 **10개 이상** 항목이 동시에 변화" — 수질+설비 혼합 기준 |

→ **12개를 구성 항목으로 열거한 곳이 원문에 없다.** 상세는 [source-inconsistencies.md](../requirements/source-inconsistencies.md) 참조.

## 4. Edge Layer (ECP)

| NPU | DEEPX DX-M1 또는 디퍼아이 NPU / AI 연산 5~10 TOPS | 국산 NPU 우선 | 사업계획서 p.57 |
| CPU | ARM Cortex-A53 Quad-core 1.5GHz | 범용 연산 | 사업계획서 p.57 |

| Storage | 64GB eMMC | 로컬 데이터 저장 | 사업계획서 p.57 |
| 통신 | LTE Cat.4(주) / Wi-Fi 802.11ac(부) / Ethernet 100Mbps(옵션) | 이중화 통신 | 사업계획서 p.57 |
| 전원 | DC 12V, 2A / 평균 소비 전력 15W | PoE 옵션 가능 | 사업계획서 p.57 |
