| | |

## 1. `[TBD-52]` 6시간 예측의 대상 항목 — **가장 급하다**

**막힌 것** — 오염도 추정 화면의 **예측 곡선을 한 줄도 못 그린다.** 과제의 성과지표이자 화면 이름이 걸린 기능이다.

**지금 하는 것** — 최근 6시간 관측 계열만 그리고, 미래 구간 자리는 음영으로 비워 둔다. 화면에 *"향후 6시간 예측은 그리지 않습니다 — 예측 대상 항목과 입력 데이터가 정해지지 않았습니다"* 를 적는다.

**어디까지 정해져 있나**

| | |
|---|---|
| 원문 | *"LSTM 기반 수질 변화 간접 추정 — TOC·TN·TP의 1~6시간 후 예측"* `[원문 p.30·32·65]`. 발표 p.16·17이 예측값과 신뢰구간을 그린 화면 예시까지 둔다 |
| 회의 | **TN·TP로 6시간을 예측하는 것이 아니다** `[회의 2026-08-20]`. TN·TP는 소프트 센싱으로 **지금 값**을 추정하는 항목이고, 6시간 예측은 실제로 재는 항목으로 이야기해야 한다 |
| 남은 것 | 회의가 든 *"TOC·유량·유입 유량·유출 유량 등"* 은 **후보를 예시로 든 것**이다. **정해진 것이 전혀 없다** `[사용자 확인 2026-08-25]` |

**물을 것 셋**

1. **예측 대상 항목을 무엇으로, 몇 개** 할 것인가
2. **신뢰구간을 낼 것인가** — 발표 p.16이 `예측 범위`를 그렸는데 대상이 바뀌었다
3. 유입·유출을 예측의 **입력**으로 쓸 것인가 — `[원문 p.24]`의 지연 응답(유입 부하 ↑ → 2~4시간 뒤 TOC ↑ → 6~12시간 뒤 TN 변화)이 근거로 있다

> **입력과 대상은 다른 물음이다.** `[원문 p.24]`는 유입이 예측 **입력**으로 유력하다는 근거이지 **대상**이라는 근거가 아니다.

## 2. 유입·유출 유량계를 각각 두는가 — **지금 화면이 틀린 말을 하고 있다**

**막힌 것** — 계측 채널이 `flow`(유량) 하나뿐인데 **화면 세 곳이 그것을 서로 다른 것이라고 부른다.**

```
/process  유입 및 전처리      "유입 유량과 유입펌프 전류"     → 유입으로 읽는다
/process  고도처리·소독·방류   "방류구 프로브 … + 방류 유량"   → 방류로 읽는다
/optimization  펌프 속도 권장  "유입 부하가 늘었다"           → 유입으로 읽는다
```

**같은 숫자를 유입이라고도 방류라고도 부르므로 한쪽은 틀렸다.** 둘은 같은 값일 수 없다 — 증발·슬러지 반출·누수만큼 차이가 나고, **그 차이가 방류 의심 판정이 보려는 것**이다(들어온 양보다 나간 양이 많으면 우회 방류를 의심한다).

**지금 하는 것** — `inflow`(유입)·`flow`(유출) 두 코드를 쓴다 `[사용자 결정 2026-08-25]`. **`outflow`가 아니라 `flow`다** — 기존 코드를 유출로 확정했다(커밋 `d1fb6b3`).

> **[2026-08-28] 채널이 생겼다.** 백엔드가 `flowIn`·`flowOut`을 신설해 **값이 실제로 들어온다**(24시간 전 구간 1분 소급 백필). 화면의 `계측 없음` 자리는 채워졌다.
>
> **그래도 이 안건은 그대로 유효하다** — 물음은 *"실증 사업장에 유량계를 몇 대 두는가"* 라는 **하드웨어** 문제이고, 채널이 생긴 것은 그 답이 아니다.
>
> **오히려 근거가 강해졌다.** 지금 들어오는 값이 물리적으로 말이 안 된다:
>
> ```
> 유입 35~1892 (50배 변동)   유출 0~1000
> 중앙값은 유입 749 > 유출 646 로 방향은 맞다
> 그런데 유입 < 유출 역전이 사업장마다 26~42%
> ```
>
> 역전이 3분의 1이면 **방류 의심의 보조 근거로 쓸 수 없고**, 화면의 `나간 양이 더 많다` 표시가 상시로 뜬다. 실제 공정에서 유입이 유출의 1/10로 떨어지는 일은 드물다. **정상 범위를 함께 물어야 한다.**

**근거의 무게를 갈라 둔다**

| | 내용 | 무게 |
|---|---|---|
| PM(수처리 박사) 의견 | **유입·유량·유출이 중요하다** | `[PM 의견 2026-08-25]` — 도메인 전문가 판단 |
| 부착 구성 | 유입에 pH 미터·유량계, 유출에 유량계·수위계 | **추측이다** `[추측 2026-08-25]` — 근거로 쓰지 않는다 |
| 원문 | 배출 데이터를 **`유량 · 수위 · 방류 여부` 3종**으로 묶는다 `[원문 p.1]` | 수위에 원문 근거가 **있다.** 다만 계측 사양표(p.55)에는 유량만 있어 원문 안에서 갈린다 |

**물을 것** — 비TMS 사업장 한 곳에 유량계를 **몇 대** 두는가. 하나뿐이라면 그것은 **유입인가 방류인가**.

## 3. 유량의 단위와 측정 지점 `[TBD-43]`

**막힌 것** — 어느 공정 단계의 물을 재는지, 어떤 단위로 받는지가 정해지지 않았다. 약품 주입 최적화는 **반응조 상태**를, 배출 감시는 **방류수**를 봐야 하는데 다항목 프로브는 1식이다.

**지금 하는 것** — 원문 사양대로 `m³/day`를 쓴다 `[원문 p.55]`.

> **[2026-08-28] 백엔드가 한 표를 던졌다.** 계측 API 채널 사전이 `flow`를 **`㎥/day` · 범위 0~1000**으로 규정한다(`docs/integration/ThingsBoard_Telemetry_API_2026-08-24.pdf` §5) — 원문 사양과 같다. **단위 물음(1번)은 사실상 정리됐고, 측정 지점(2·3번)만 남았다.**

**갈려 있는 것**

| 원천 | 유량 표기 | 단위 |
|---|---|---|
| 원문 계측 사양 `[원문 p.55]` | 유량 · `Q` | `m³/day` |
| 비TMS 실측 `[데이터셋 Non_TMS_sites/01]` | `적산유량[FL00]` · `유량수위스위치[FS00]` | **적산**(누적) · 스위치 |
| TMS 실측 `[데이터셋 TMS_sites]` | `FIT-101`·`FIT-102`·`FIT-201A`·`FIT-201B` | **㎥/h** — 단계별 4대 |

**물을 것 셋**

1. 단위를 `적산` · `㎥/h` · `m³/day` 중 무엇으로 통일하는가
2. 유입은 **유입펌프 앞인가 뒤인가**
3. 유출은 **방류구인가 방류수조인가**

## 4. `[TBD-45]` 기준치를 **어떻게 받을 것인가**

**막힌 것** — 배출허용기준을 고르는 축 3종(① 지역구분 ② 1일 폐수배출량 규모 ③ 방류 경로)이 정해지지 않아, 화면이 `기준 초과`를 **판정하지 못한다.**

**지금 하는 것** — 회의가 우회로를 냈다 `[회의 2026-08-20]`: *"지역별 방류 기준이 다르므로 그 값을 입력하는 화면을 두고, 우리는 기본값을 채우지 않는다."* 그리고 **기초지자체가 입력한다**로 정했다 `[사용자 결정 2026-08-25]` — 지역별 기준을 아는 주체가 지자체다.

> **우리가 법정 판정값을 채우지 않는 것은 규칙이다.** 법령이 원천이고 우리가 정하면 그냥 틀린 값이 된다. 회의가 1순위가 되어도 이 항목은 예외다(`deliverable-xlsx.rule.md` §4.3).

**물을 것 둘 — 운영 방식이다**

1. 지자체가 관내 사업장의 기준치를 **일괄로 넣는가, 사업장마다 넣는가**
2. 지금 사업장도 갖고 있는 편집 권한을 **내릴 것인가** — 두 주체가 같은 값을 고치면 마지막에 쓴 쪽이 이긴다

**답에 따라** — 기준치가 들어오면 오염도 추정 화면의 수질 차트가 **비어 있다가 그려지기 시작한다.** 기준 대비 축을 쓰기 때문이다(→ `2026-08-25_오염도추정-재설계.md` §4.4).

## 5. `[TBD-46]` 방류 의심 판정의 임계값

**막힌 것** — 무엇을 무단으로 볼지가 없다. 신고된 방류 시간대·유량 한도·허용 방류 경로 중 무엇을 기준으로 삼는지 정해지지 않았다.

**지금 하는 것** — 판정 **방법**은 원문에 있다. 발표 p.14가 *"무단방류 의심 패턴 감지 — **유량·전류 관계 기반** 비정상 패턴 식별"* 이라 적는다 `[원문 발표 p.14 그림]`. 그래서 `방류 중 ∧ 방지시설 미가동`이 연속되는 구간을 잡고, **연속 길이 임계값만 `[PROVISIONAL]`** 로 둔다.

**물을 것** — 몇 분 이상 연속되면 의심으로 볼 것인가. 유량 한도를 함께 볼 것인가.

**답에 따라** — 기초지자체 화면의 본론이 이 판정이다. 임계값이 바뀌면 관내 목록의 `방류 의심 N구간`이 통째로 달라진다.

## 6. `[TBD-51]` 약품 투입량 산정 공식

**막힌 것** — 주입량을 계측에서 낼 수 없다. 지금 화면의 현재·권장 주입량은 **이상 점수 세기로 만든 합성값**이고, 유량계·약품 탱크 개념이 코드에 없다.

**지금 하는 것** — 단위를 `L/h`로 가정하고 `[PROVISIONAL]`로 표기한다. 액상 응집제 주입 펌프를 가정한 시연 표기다.

**물을 것** — 주입량을 무엇으로 산정하는가(유량 × 농도 × 계수?). 단위와 범위는 무엇인가.

## 7. `[TBD-49]` 진동 센서 사양

**막힌 것** — 설비 이상 탐지의 **주 입력**인데 무엇으로 재는지가 없다. 화면이 값의 단위와 자릿수를 정할 수 없다.

**지금 하는 것** — 사양 없이 항목만 등재하고 **이상 여부만 표시, 값은 내지 않는다.**

**어디까지 정해져 있나** — 채용은 정해졌다. 목표시스템 그림이 *"설비 이상징후 탐지 — 진동, 전류, 유량 등"* `[원문 발표 p.11 그림]`, 출력 화면 예시에 `진동 이상`이 알림 유형으로 있다 `[원문 발표 p.18 그림]`. 그런데 계측 사양표(p.55)에는 전류·전력·유량 3종뿐이다.

**물을 것** — 가속도 RMS인가 속도인가. 단위·범위·정확도.

## 9. `[TBD-55]` 회의 피드백 4번의 뜻

**막힌 것** — *"AI 모델과 대상지 분리"* 라는 피드백을 받았는데 **무엇을 분리하라는 것인지 모른다.** 작업자도 뜻을 확인하지 못했다.

**물을 것** — 무엇과 무엇을 분리하라는 것이었는가.

## 10. `[INC-94]` 운영 최적화를 기초지자체에 열어 둘 것인가

**막힌 것** — `운영 최적화` 화면은 **약품 주입량 권장**을 낸다. 감독 기관이 사업장의 운전 조건을 권하는 것이 맞는지 원문이 정하지 않는다.

**지금 하는 것** — 열려 있다(`R`).

**어디까지 정해져 있나** — 원문 접근제어는 *"운영자 = 모니터링, 알람 확인"* `[원문 p.69]`인데, 같은 원문의 사용자 기능 목록에 *"약품 주입량 최적화 제안"* 이 있고 **역할 배정이 없다** `[원문 p.31~32]`.

**물을 것** — 지자체 계정에 운영 권고 화면을 열어 두는 것이 맞는가.

> 알람 확인(`U`)은 **주지 않기로** 정했다 `[사용자 결정 2026-08-25]`. 그쪽은 **조작 권한**이고 이쪽은 **권고를 보여 줄 것인가**라 축이 다르다 — 같이 묶어 판단하지 않았다.

## 11. `DO`가 어느 지점의 값인가 — **화면이 오독을 부른다** `[2026-08-28 신설]`

**막힌 것** — 화면이 `용존산소`라고만 적는다. 그런데 실제로 오는 값은 **0.22~1.67 mg/L**다. 방류수 DO로 읽으면 **산소 결핍 상태**로 보인다.

**무엇이 밝혀졌나** — 계측 API 명세가 못박는다 `[데이터셋 ThingsBoard_Telemetry_API §5.2]`:

> *"생물반응조 폭기조 DO다. 미생물이 산소를 소비하는 곳이라 0.4 안팎이 정상이며, 방류수 DO(5 안팎)와 다른 값이다. 화면이 어느 지점의 값인지 적어야 한다 — 안 적으면 방류수가 산소 결핍이라고 읽힌다."*

**우리 시연 fixture는 5.4**(방류수 DO 기준)라 **실측과 10배 이상 다르다.** 어느 쪽이 맞는지가 아니라 **어느 지점을 재기로 했는지**가 정해져야 한다.

**물을 것 셋**

1. 다항목 프로브가 **폭기조**에 있는가 **방류구**에 있는가 (안건 3의 측정 지점 물음과 같은 뿌리다)
2. 폭기조라면 화면 라벨을 `용존산소(폭기조)`로 바꾸는가 — **배출 감시 화면에 공정 내부 값이 있는 것이 맞는가**
3. 방류수 DO도 필요하면 프로브가 하나 더 필요한가

## 12. 수집 주기가 원문과 다르다 `[INC-111]` `[2026-08-28 신설]`

**막힌 것** — 막힌 것은 없다. **심사 자리에서 지적이 나올 수 있어** 미리 정리해 두는 항목이다.

| | |
|---|---|
| 원문 | `5분 단위 + AI 추론` `[원문 발표 p.7 그림]` — 수동 자가측정 `월·분기 1회` · 수질TMS `5분 단위`와 나란히 비교하는 표다 |
| 원문 텍스트 | `1~10분(설정 가능)` `[원문 p.30·48]` |
| 실증 장비 | **1분** `[사용자 확인 2026-08-27]` |

**모순은 아니다** — 1분은 원문 텍스트의 범위 안이다. 어긋나는 것은 **발표 그림의 `5분`** 하나이고, 그 표가 TMS 대비 우위를 말하는 자리라 **더 조밀해진 것은 유리한 방향**이다.

**물을 것** — 발표자료·산출물에서 `5분`을 `1분`으로 고칠 것인가, 아니면 *"1~10분 설정 가능, 실증은 1분"* 으로 적을 것인가. **화면은 이미 1분으로 돌고 있다.**
