#### 4. 유량·유입·유출 표출 설계

##### 지금 상태

| | |
|---|---|
| 계측 코드 | **`flow` 한 종뿐**. 유량 · `Q` · `m³/day` · 0~1,000 · ±2% `[원문 p.55]` |
| 통합 관제 계측 격자 | 수질 8종만(`WATER_SERIES_CODES`). **유량이 없다** |

| 유입·유출 | **채널이 없다** |

##### 데이터 문제 셋

**① 유입·유출을 나눠 재는 채널이 없다.** 원문 계측 사양에 유량은 한 종이다 `[원문 p.55]`. 회의에서 *"TOC·유량·유입 유량·유출 유량 등"* 이라는 말이 나왔지만 `[회의 2026-08-20]` **그것은 후보를 예시로 든 것이고 정해진 것이 아니다** — `[TBD-52]`가 *"항목 후보만 있다"* 로 적고 있다.

그래서 이 절이 만드는 유입·유출 칸은 **예측이 아니라 지금 값**이다. 회의 피드백이 요구한 자리가 `수질·설비 실시간 계측`이라 그렇다 — 예측 쪽은 `/prediction` 절에서 따로 다루고, **그쪽은 설계하지 않는다.**

**② 실측 데이터의 유량 축이 셋이다.** 데이터셋을 열어 확인했다.

| 원천 | 유량 컬럼 | 단위 |
|---|---|---|
| 비TMS 진유원 `[데이터셋 Non_TMS_sites/01]` | `적산유량[FL00]` · `유량수위스위치[FS00]` | **적산**(누적) · 스위치(ON/OFF) |
| 비TMS 진유원 `[데이터셋 Non_TMS_sites/04]` | `유량` · `전류계위치 = 유입펌프` | 시간·일 단위 집계 |
| **TMS 매일유업** `[데이터셋 TMS_sites]` | **`FIT-101`(스크린조) · `FIT-102`(집수조) · `FIT-201A`·`FIT-201B`(반응응집·1차침전)** | **㎥/h** — 단계별 |
| 우리 코드 | `flow` | `m³/day` `[원문 p.55]` |

즉 **유입·유출 분리는 도메인에 실재한다** — TMS 급 설비에는 단계별 유량계가 넷 있다. 다만 **우리 대상(비TMS)에는 적산유량 하나**이고, 단위도 `적산`·`㎥/h`·`m³/day` 셋으로 갈린다.

**③ 지금 `flow`가 두 뜻으로 쓰이고 있다.** 이건 기존 결함이다.

```
/process  유입 및 전처리     defaultCodes: ['flow','current']
          "유입 유량과 유입펌프 전류"           ← 유입으로 읽는다
/process  고도처리·소독·방류  defaultCodes: [...수질8,'flow']
          "방류구 프로브 … + 방류 유량"        ← 방류로 읽는다
/optimization  OperatingSignal.flow
          "유입 유량 최근/직전 구간 평균과 그 비율"  ← 유입으로 읽는다
```

같은 계열을 유입에도 방류에도 붙였으므로 **하나는 틀린 셈이다.** 유입·유출을 나누면 이 셋이 함께 정리된다.

##### 표출 설계

**격자를 하나로 늘리지 않고 소절을 나눈다.**

```
┌ 수질·설비 실시간 계측 ────────────────────────────────┐
│ 수질 8종                                              │
│ ┌────┬────┬────┬────┐                                │
│ │ pH │ DO │ EC │Turb│                                │
│ ├────┼────┼────┼────┤                                │
│ │TOC │NO₃ │Temp│Color│                               │
│ └────┴────┴────┴────┘                                │
│ ─────────────────────────────────────────────────── │
│ 유량 — 들어온 양과 나간 양                              │
│ ┌──────────┬──────────┬──────────┐                   │
│ │ 유입      │ 유출      │ 총량(적산) │                  │
│ │ 계측 없음  │ 계측 없음  │  312     │                  │
│ │ [TBD-52] │ [TBD-52] │  m³/day  │                  │
│ └──────────┴──────────┴──────────┘                   │
└──────────────────────────────────────────────────────┘
```

**왜 소절을 나누는가** `[설계]`

- 원래 유량을 뺀 이유가 *"11칸을 한 격자에 넣으면 단위가 값에 가려진다"* 였다. **소절로 나누면 그 이유가 해소된다** — 격자는 각각 4칸·3칸이라 어긋나지 않는다
- 수질은 **농도**(mg/L·NTU·pH), 유량은 **부피/시간**이다. 축이 다른 것을 한 격자에 섞으면 옆 칸과 비교된다는 잘못된 신호를 준다
- **유입·유출·총량은 서로 비교되어야 뜻이 생긴다** — 들어온 양과 나간 양이 맞는지가 판독의 알맹이고, 그것이 방류 의심 판정(`REQ-AD-032`)과 이어진다. 나란히 두는 것이 목적이다

**없는 것을 빈 칸으로 두지 않는다** — `계측 없음 [TBD-52]`로 적는다. 저장소에 선례가 있다: `LEGAL_CHECK_ITEMS`의 SS가 `code: null`이고 화면이 `계측 없음`이라 적는다(`discharge-limits.ts` · `timeseries-view.tsx` · `discharge-limit-editor.tsx`). **빈 칸으로 두면 값을 못 받은 것으로 읽히고, `0`으로 두면 "흐르지 않았다"가 된다**(**E4**).

**총량을 `적산`이라 적는다** `[설계]`. 실측이 적산유량이라 순간 유량과 뜻이 다르다 — 그냥 `유량`이라 적으면 `㎥/h`로 읽힌다.

```ts
TOC  category: 'water'      accuracy: '±10%'     ← 계측
TN   category: 'estimated'  accuracy: 'AI 추정'   ← 소프트 센싱
TP   category: 'estimated'  accuracy: 'AI 추정'   ← 소프트 센싱
```

#### 왜 확인이 필요했나 — 원문이 어긋난다 `[INC-90]`

| 근거 | 말하는 것 |
|---|---|
| `[원문 p.55]` 계측 사양표 | TOC 센서 있음 — 광학식 · 0~500 mg/L · ±10% · 교정 월 1회 |
| `[원문 p.35]` H/W 성능지표 | TOC 포함 |
| `[원문 발표 p.17]` | *"직접 수치 계측이 **어려운** TOC, TN, TP"* |
| `[원문 p.66]` | *"고가 분석기 대체를 위한 경제적 **TOC 추정** 기능"* |

**확정은 앞의 둘이다.** 뒤의 둘은 원문 표현이 TOC를 TN·TP와 묶어 적은 것이고, 소프트 센싱 대상은 **TN·TP뿐**이다.

#### 데이터셋에 TOC가 없는 것은 모순이 아니다 — **시점 차이다**

실측 xlsx 18개를 전부 열어 확인한 결과다. 나중에 이것을 보고 "TOC는 안 잰다"고 결론 내리지 않도록 남긴다.

| 원천 | 수질 연속 계측 채널 |
|---|---|
| **진유원**(비TMS) `[데이터셋 Non_TMS_sites/01]` | pH · 탁도 · 수온 · 색도 · 전도도 — **5종.** DO·NO₃-N·TOC 없음 |
| **매일유업**(TMS 참조) `[데이터셋 TMS_sites]` | SS · pH · T-N · NH₄-N · NO₃-N · ORP · DO · MLSS — TOC 없음 |
| TOC가 있는 곳 | `05_사업장_수분석결과/3.시험성적서_IOT_진유원.pdf` — **위탁 실험실 성적서**(월 단위) |

**데이터셋은 구축 *전* 현황이고 계측 사양표는 구축 *후* 목표다.** 진유원의 기존 센서 구성에 TOC가 없었을 뿐이며, 우리가 설치하는 8종에는 있다. 두 문서가 다른 시점을 말하므로 모순이 아니다.

> **`[INC-90]`에 이 해소를 등재해야 한다** — §3에 넣었다. 지금 그 항목은 원문 두 곳만 대조하고 있고 **확정과 데이터셋 확인이 빠져 있다.**
