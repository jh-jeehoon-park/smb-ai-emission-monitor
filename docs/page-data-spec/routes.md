## 2. 이 문서의 목적과 범위

`dashboard.md`와 같은 목적이다 — 백엔드가 없어 API 갭 개념이 성립하지 않으므로(A3 미적용) **화면이 무엇을 필요로 하는지**를 남긴다. 여기서는 `/` 이외의 6개 라우트를 다룬다.

데이터 원천은 여전히 `src/shared/config/demo-scenario.ts` 하나이며, 각 화면은 `entities/<slice>/api/fixtures.ts`를 통해 읽는다. **새 도메인 값을 만들지 않았다** — 이미 대시보드가 쓰던 것과 같은 형태를 다른 밀도로 보여줄 뿐이다. 유일한 예외는 §4.3의 TN·TP 시계열이다.

---

## 3. 공통 — URL이 화면 상태를 가진다

`frontend.rule.md` **P6**에 따라 사업장·기간·항목 필터를 URL 쿼리에 둔다. 링크를 그대로 공유하면 같은 화면이 열리고, 화면을 옮겨도 선택이 유지된다.

| 키 | 값 | 사용 화면 | 기본값 |
|---|---|---|---|
| `site` | 사업장 id | 전 화면 | `DEFAULT_SITE_ID` |
| `hours` | `6` \| `12` \| `24` | 시계열 변화, 리포트 | `24` |
| `cat` | `water` \| `equipment` \| `all` | 시계열 변화 | `water` |
| `target` | `TOC` \| `TN` \| `TP` | 오염도 추정 | `TOC` |
| `sort` | `mpi` \| `failure` \| `rul` | 설비 예지보전 | `mpi` |
| `prio` | `all` \| `urgent` \| `caution` \| `info` | 알람 이력 | `all` |
| `state` | `all` \| `open` \| `acknowledged` \| `resolved` | 알람 이력 | `all` |
| `scope` | `all` \| `site` | 알람 이력 | `all` |

허용 목록에 없는 값이 들어오면 빈 화면 대신 기본값으로 되돌린다(`shared/lib/use-query-state.ts`).

> 이 때문에 전 라우트가 동적 렌더(`ƒ Dynamic`)다. 정적 프리렌더는 쿼리를 모르므로 사이드바가 스켈레톤으로 굳는다. 실시간 관제 화면이라 손해가 없다.

## 4. 화면별 요구 데이터

### 4.1 이상 탐지 `/anomaly` — FR-06·07·08·09·14

기존 대시보드 패널 두 개를 전체 폭으로 키우고 **사업장 간 비교**를 더했다.

| 영역 | 요구 데이터 | 비고 |
|---|---|---|
| 이상 점수 타임라인 | `AnomalyPoint[]` + 결측 구간 | 대시보드와 동일 |
| 이상 탐지 결과 | `AnomalySummary`(점수·등급·산출 시각·대상 기간·기여 변수) | E3 — 값과 근거를 함께 |
| **사업장별 이상 점수** | 사업장 10개소의 최신 점수·등급 + 최근 추이 스파크라인 | **신규.** 한 사업장만 보면 그 점수가 높은지 알 수 없다 |
| 관련 알람 | `condition === 'anomaly'`인 알람 | 조건별 필터링만 추가 |

통신 두절 사업장은 점수를 0으로 내리지 않고 목록 끝에 `수신 없음`으로 남긴다(E4).

### 4.2 시계열 변화 `/timeseries` — FR-01·05

| 영역 | 요구 데이터 | 비고 |
|---|---|---|
| 계측 그리드 | `MeasurementPoint[]`를 선택 기간으로 자른 것 | 항목 집합은 `cat`이 정한다 |
| **항목별 요약** | 항목마다 최소·평균·최대·최신·결측 표본 수 | **신규.** `entities/measurement/lib/series-stats.ts` |

**결측은 통계에서 제외하고 건수로만 센다.** 0으로 치면 최소·평균이 함께 거짓이 된다(E4).

수집 주기(5분)와 조회 기간을 화면에 함께 적는다(E5). 원문의 수집 주기는 1~10분 설정 가능이며(FR-05) 프로토타입은 5분 고정이다 — **주기 변경 UI는 만들지 않았다.** 설정 저장소가 없다.

### 4.3 오염도 추정 `/prediction` — FR-10·11·12·15

**이 화면에서만 fixture를 확장했다.** 기존에는 TOC 시계열만 있고 TN·TP는 경향값만 있어 FR-12가 반쪽이었다.

| 항목 | 계측 여부 | 예측 시계열 | 근거 |
|---|---|---|---|
| TOC | 센서 계측 O | 신규 추가 전에도 있었음 | 사업계획서 p.55 |
| TN | **센서 없음** | **신규** | 발표자료 p.17 — AI 추정(Soft Sensing) 대상 |
| TP | **센서 없음** | **신규** | 동일 |

항목마다 값의 자릿수가 다르므로(TOC ~25, TN ~16, TP ~1.5) 프로파일을 `entities/prediction/config/constants.ts`에 두고 계열을 생성한다. **소수 자릿수·단위는 항목별로 고정**한다(E1).

경향 요약(상승/유지/하락)은 어느 항목을 보고 있든 세 항목을 함께 보여주며, 값은 각 항목의 예측 마지막 지점에서 가져온다 — 차트와 카드가 어긋나지 않는다.

> **백엔드 착수 시 확인할 것:** 신뢰구간의 신뢰수준(95%? 90%?)이 원문에 없다. 지금은 시간에 비례해 벌어지는 폭으로만 그린다.

### 4.4 설비 예지보전 `/equipment` — FR-13·19·20·21

| 영역 | 요구 데이터 | 비고 |
|---|---|---|
| 설비 상태 요약 | `Equipment[]` (고장 확률·잔여 수명·MPI·등급) | 대시보드와 동일 |
| 설비 상세 표 | 위 + 누적 가동시간 | 정렬 기준 3종 |
| **유지관리 우선순위 추천** | 전 사업장 설비를 MPI 한 줄로 | **신규 — FR-21** |
| 관련 알람 | `condition === 'equipment'`인 알람 | |

**통신 두절 사업장은 설비 지표를 보여주지 않는다.** 계측·이상 점수·예측이 전부 결측인데 설비만 멀쩡한 숫자를 띄우면 한 화면이 서로 다른 말을 한다. 전 사업장 순위에서도 제외하고 제외 사실을 화면에 적는다.

> **미정:** MPI 산정식·값 범위·단위가 원문에 없다(TBD-22). 0~100 상대 지수로만 표시하고 산식을 세우지 않았다. 화면에도 그렇게 적는다.

### 4.5 알람 이력 `/alarms` — FR-27·28·30

| 영역 | 요구 데이터 | 비고 |
|---|---|---|
| 요약 타일 | 미확인·미조치 긴급·조치 완료 건수 | 상태를 바꾸면 즉시 반영 |
| 알람 목록 | `Alarm[]` 전체, 발생 시각 내림차순 | 우선순위·상태·사업장 범위로 필터 |
| 상태 전이 | `open → acknowledged → resolved` 단방향 | |

**상태 전이는 브라우저 메모리에만 남는다.** 서버가 없어 저장할 곳이 없고 새로고침하면 fixture로 돌아간다. 화면에 그 사실을 적고 되돌리기 버튼을 둔다 — 시연 중 원상복구가 필요하다.

> **미정 (TBD-21):** 알람 우선순위 3단계(긴급/주의/정보)와 상태 등급 4단계(정상/주의/경고/위험)의 대응 관계가 원문에 없다. **임의로 매핑하지 않았다.**
> **미구현:** 발송 채널(SMS·이메일·푸시)은 발송 주체가 서버다. 채널 설정 UI를 만들면 동작하지 않는 화면이 된다.

### 4.6 리포트 `/reports` — FR-38

원문이 **리포트 항목·양식·발행 주기를 규정하지 않았다.** 그래서 화면에 이미 있는 값만 모으고 새 지표를 만들지 않았다.

| 열 | 출처 |
|---|---|
| 사업장·지역·업종·상태 등급 | `Site` |
| 최신·최대·평균 이상 점수 | 이상 점수 계열을 선택 기간으로 자른 것 |
| 결측 표본 / 전체 표본 | 위 계열의 null 개수 |
| 알람 건수 (긴급·주의·정보) | `Alarm[]` |
| 데이터 처리율·가동률 | `Site` |

CSV 내보내기는 실제로 동작한다(UTF-8 BOM 포함 — 엑셀이 한글을 깨뜨리지 않게). **값이 없는 칸은 0이 아니라 빈 칸**으로 내보낸다. 표의 `—`와 같은 뜻이어야 한다.

> **미정:** 일간·주간·월간 같은 발행 주기와 법정 서식을 만들지 않았다. 집계 구간도 시연 데이터가 가진 축적 구간 24시간(사업계획서 p.65) 안에서만 고른다.
