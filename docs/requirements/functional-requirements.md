## 2. 문서의 성격과 한계

### 2.1 이 문서가 담는 것

원문(사업계획서 `HSKorea_AI_Application_Proposal.pdf`, 발표자료 `AIoT_Emission_Control_System.pdf`)이 **"시스템이 제공한다"고 명시한 기능**만 옮긴 것이다. 각 서술의 출처 페이지를 붙여 추적 가능하게 했다.

### 2.2 이 문서가 담지 않는 것

| 항목 | 사유 |
|------|------|
| 화면 설계·와이어프레임·UI 시안 | 원문에 없음. 이후 별도 작업 |
| 정보구조(IA)·메뉴 체계 | 원문에 없음 |
| 컴포넌트 구조·상태 전이 | 원문에 없음 |
| 화면별 표시 항목의 배치·우선순위 | 원문에 없음 |

원문이 "이상 점수를 실시간 표시한다"(발표자료 p.15)라고 규정한 경우, 이 문서는 **"원문이 그렇게 규정한다"는 사실**만 기록하며 그것을 어떤 위젯·레이아웃으로 구현할지는 판단하지 않는다.

### 2.3 원문 페이지 표기 규칙

- `사업계획서` = `HSKorea_AI_Application_Proposal.pdf`
- `발표자료` = `AIoT_Emission_Control_System.pdf`
- 페이지 번호는 **PDF 파일 페이지 번호**다(문서 하단에 인쇄된 본문 쪽번호와 다르다. 예: 사업계획서 PDF p.28 = 인쇄 쪽번호 23).

### 2.4 원문 간 모순 표기

두 원문 또는 같은 원문 내에서 값이 다를 경우 **둘 다 적고 `⚠ 모순`** 을 표기한다. 상세 대조는 [source-inconsistencies.md](source-inconsistencies.md)를 참조한다.

### 2.5 텍스트 추출 한계

원문 다수 페이지의 표·도식이 이미지로 처리되어 텍스트 추출이 되지 않았다. 특히 **그림 2-8 「실시간 수질 모니터링 장비 및 알림 대시보드」(사업계획서 p.69)** 는 대시보드 화면 구성의 직접 근거임에도 캡션만 남아 있다. 또한 사업계획서 p.68의 "4) 실시간 데이터 수집 → AI 분석 → 알람 발송" 다음이 p.69의 "6) 보안 및 데이터 관리"로 이어져 **"5)" 항목의 텍스트가 통째로 누락**되어 있다(사업계획서 p.68, p.69). 대시보드 상세 설명이 이 누락 구간에 있었을 가능성이 있어 **원본 PDF 표·그림 확인 필요**다.

## 3. 사용자 및 권한

### 3.1 역할별 권한 (원문 표기 그대로)

원문이 권한 체계를 규정한 곳은 사업계획서 p.69 "6) 보안 및 데이터 관리 — 접근제어" 한 곳뿐이다.

| 역할 | 원문이 규정한 권한 | 출처 |
|------|-------------------|------|
| 관리자 | 모든 기능 접근 | 사업계획서 p.69 |
| 운영자 | 모니터링, 알람 확인 | 사업계획서 p.69 |
| 게스트 | 조회만 가능 | 사업계획서 p.69 |

권한 관리 방식은 **RBAC(Role-Based Access Control)** 로 명시된다(사업계획서 p.69).

> 위 3개 외의 역할은 원문에 없다. 추가하지 않는다.

## 8. 화면 기획 전 확정이 필요한 항목

원문에 없어 화면 설계 착수 전 결정이 필요한 항목이다. 각 항목마다 **왜 필요한지**와 **원문에서 관련 서술이 어디까지 있는지**를 적었다.

| ID | 항목 | 왜 필요한지 | 원문에서 관련 서술이 어디까지 있는지 |
|----|------|-------------|-------------------------------------|
| TBD-01 | **상태 등급 체계 통일** | 상태 배지·색상·필터의 기본 축이다. 등급 수(2/3/4)가 확정되지 않으면 대시보드 전체의 상태 표현을 설계할 수 없다 | 원문에 4가지 체계가 병존한다: 정상/이상(사업계획서 p.30, p.31), 정상/주의/이상(사업계획서 p.64), 정상/주의/경고/위험(발표자료 p.15), 정상/주의/위험(발표자료 p.17), 정상/주의/경고/위협(발표자료 p.18). 어느 것이 최종인지의 서술은 **원문 없음** |
| TBD-02 | **알람 임계값·판정식** | 알람 목록·설정 화면의 입력 항목과 검증 규칙을 정의할 수 없다 | "설정된 임계값 초과 시"(사업계획서 p.68)라는 표현까지만 있다. 항목별 임계값 수치, 복합 이상 판정식은 **원문 없음**. 오히려 단일 임계값 방식의 한계만 기술된다(사업계획서 p.61) |
| TBD-03 | **이상 점수 구간 → 상태/우선순위 매핑** | 이상 점수(0~100)를 어느 구간에서 어떤 상태·알람 우선순위로 표기할지 결정해야 게이지·배지를 설계할 수 있다 | 이상 점수 범위 0~100(사업계획서 p.64), 상태 분류 3종(사업계획서 p.64), 알람 우선순위 3종(사업계획서 p.32)까지 있다. **구간 경계값과 두 축의 대응 관계는 원문 없음** |
| TBD-04 | **오염도 추정 결과의 표시 형태** | 수치 예측(값+신뢰구간)과 경향성 3분류(상승/유지/하락)는 차트 형태가 완전히 다르다 | 사업계획서 p.32·p.65는 수치+신뢰구간, 발표자료 p.17은 경향성 3분류. 두 표현을 동시에 제공하는지 택일인지는 **원문 없음** |
| TBD-05 | **화면 구성·화면 목록** | 어떤 화면이 몇 개 존재하는지가 정해지지 않았다 | 대시보드 3종의 **이름**만 있다: 이상탐지 대시보드(예시), 시계열변화 대시보드(예시), 오염도추정 대시보드(예시)(발표자료 p.15·p.16·p.17). 사업계획서는 "실시간 모니터링 + AI예측 + 알람 통합 제공"(p.45)까지. 화면 목록·레이아웃·위젯 명세는 **원문 없음**(그림 2-8은 이미지, 사업계획서 p.69) |
| TBD-06 | **기간 필터 / 조회 범위** | 시계열 차트의 기본 조회 범위와 선택 가능한 프리셋을 정할 수 없다 | 수집 주기 1~10분(사업계획서 p.30·p.48), 학습 축적 구간 24~72시간(사업계획서 p.65, 발표자료 p.15), 예측 구간 1~6시간(사업계획서 p.32), 로컬 보존 7일(사업계획서 p.30), 장기 보관 3년 이상(사업계획서 p.69)까지 있다. **화면의 기간 필터 옵션 자체는 원문 없음** |
| TBD-07 | **리포트 양식·항목·주기** | 리포트 생성/열람 화면을 설계할 수 없다 | "유지관리·리포트·운영지원 포함 통합 서비스 제공"(발표자료 p.32)까지. 리포트 종류·항목·주기·출력 포맷은 **원문 없음**. 참고로 검증 지표(R², MAE, 탐지 정확도, 오탐/미탐률, 가동률 ≥95%)는 사업계획서 p.38에 있고, 비용 절감 항목(TMS구축 비용·약품비·에너지비·사고 대응 비용·총절감액)은 사업계획서 p.40에 표로 있다 |

| TBD-09 | **알람 관리 절차** | 알람 목록의 액션(확인/해제/담당자 지정)과 상태 컬럼을 정의할 수 없다 | "알람 및 이벤트 관리"(사업계획서 p.50), "알람 이력"(발표자료 p.15)까지. 확인(ack)·해제·에스컬레이션·수신자 지정·재발송 규칙은 **원문 없음** |
