## 2. 문서의 목적과 사용법

### 2.1 목적

이 대장은 사업계획서(HSKorea_AI_Application_Proposal.pdf)와 발표자료(AIoT_Emission_Control_System.pdf) 두 원문에서 **서로 어긋나는 값**, **원문에 정의가 없어 설계를 진행할 수 없는 항목**, **이미지로만 존재해 텍스트로 확인할 수 없는 내용**을 한 곳에 모은 것이다. 설계·개발에 착수하기 전에 사용자에게 확인해야 할 목록이다.

### 2.2 원칙

1. **임의 판단으로 어느 한쪽을 채택하지 않는다.** 두 값이 다르면 둘 다 적고, 확정은 사용자 확인을 거친다.
2. **원문에 없는 값을 추론으로 채우지 않는다.** 계산상 자연스러운 값이라도 원문에 없으면 `[TBD]`로 남긴다.
3. **수치는 원문 그대로 옮긴다.** 반올림·단위 환산·오타 보정을 하지 않는다. 오타로 보이는 표기는 §6에 별도로 기록하고 본문에서는 원문 표기를 유지한다.
4. **다른 산출 문서가 이 대장을 참조한다.** 다른 문서에서 모순 값을 서술할 때는 `⚠ 모순` 표기와 함께 이 문서의 INC 번호를 인용한다.

### 2.3 사용법

| 상황 | 참조 섹션 |
|------|-----------|
| 두 원문의 값이 달라 어느 쪽을 쓸지 판단해야 할 때 | §3 |
| 설계에 필요한 값이 원문에 아예 없을 때 | §4 |
| 표·그림이 텍스트로 추출되지 않아 값을 확인할 수 없을 때 | §5 |
| 용어·표기가 문서마다 다를 때 | §6 |
| 확인 요청을 언제 누구에게 할지 정할 때 | §7 |

### 2.4 심각도 정의

| 등급 | 기준 |
|------|------|
| 높음 | 확정 전에는 설계·구현을 시작할 수 없다(자료구조·상태 정의·아키텍처 계층·핵심 성능 목표 등) |
| 보통 | 설계는 진행 가능하나 값 확정 없이는 문서·산출물을 완결할 수 없다(비용·건수·일정 등) |
| 낮음 | 표기·계산 오차 수준으로, 문서 정합성 정리 시 해소 가능하다 |
