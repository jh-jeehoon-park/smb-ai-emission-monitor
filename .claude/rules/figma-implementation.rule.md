## 2. 목적 & 범위

Figma MCP로 **node-id를 추적**하여 UI 컴포넌트·페이지를 구현할 때, **Figma 디자인에서 벗어나지 않고 임의로 판단하지 않도록** 하는 규칙이다. 적용 대상은 본 저장소의 웹 대시보드 프론트엔드다. 백엔드·Edge 코드에는 적용하지 않는다.

- 본 프로젝트 Figma fileKey: **[TBD]** — 확정 전에는 사용자에게 대상 파일/노드 URL을 요청한다.
- 디자인 토큰·컴포넌트 node-id 색인 문서: **[TBD]** (확정 시 `docs/design-system.md`로 등록하고 단일 참조원으로 삼는다).
- 위 두 값이 [TBD]인 동안에는 **디자인 기반 구현을 임의로 시작하지 않는다.** 사용자가 준 node URL이 있을 때만 §5 절차로 진행한다.

## 3. 절대 원칙 (D1~D6) — 위반 시 즉시 멈춰 사용자에게 보고

| # | 원칙 |
|---|------|
| **D1** | **디자인 이탈 금지.** 색·타이포·간격·크기·radius·레이아웃·계층·상태를 Figma node 데이터/스크린샷 **그대로** 반영한다. 눈대중·근사치 금지 |
| **D2** | **임의 판단·창작 금지.** 디자인에 없는 값·요소·상태·문구·아이콘·애니메이션을 추측하거나 추가하지 않는다. 근거는 항상 node 데이터다 |
| **D3** | **디자인 토큰 우선.** Figma 변수(토큰)를 프로젝트 디자인 토큰(`shared/config`)으로 **매핑해서 사용**한다. 임의 hex·arbitrary px 하드코딩 금지(frontend.rule.md R9) |
| **D4** | **공용 컴포넌트 재사용 우선.** 디자인시스템 배리언트(Button/Chip/StatusTag 등)는 `shared/ui`의 기존 컴포넌트로 구현한다. 인라인 재구현 금지(frontend.rule.md R10) |
| **D5** | **추적성 유지.** 구현 산출물(컴포넌트/PR)에 출처 node-id를 남긴다(예: 상단 주석 `// figma: 23:15 Button/Primary/Large`) |
| **D6** | **불명확·괴리 시 임의 결정 금지.** 디자인에 없거나 모순되면 §8 절차(확인 요청·문서 등록)를 따른다. 추측으로 채우지 않는다 |

## 4. node-id 추출 규칙

- Figma URL `.../design/:fileKey/:name?node-id=1-2` → **fileKey=`:fileKey`, nodeId=`1:2`** (URL의 `1-2`는 `1:2`로 변환).
- node-id가 없는 URL은 진행하지 말고 **node 지정 URL을 요청**한다(임의로 페이지 전체를 가정하지 않는다 — D2).
- 토큰/공용 컴포넌트는 URL이 아니라 **디자인시스템 색인 문서의 node-id**를 우선 사용한다(색인 문서 확정 전에는 §2에 따라 [TBD]).

## 5. MCP 조회 절차 (순서 준수)

프로젝트 Figma MCP 서버(`.mcp.json`의 `figma`=figma-developer-mcp)를 사용한다. 각 단계는 **추측이 아니라 데이터 확보**가 목적이다.

1. **구조 파악** — `get_figma_data(fileKey, nodeId)` (또는 metadata)로 레이어 트리·이름·타입·크기·위치 확보.
2. **정밀 스펙** — 필요한 하위 node의 색/타이포/간격/오토레이아웃/제약을 node 데이터로 확정. 스크린샷으로 **시각 대조**.
3. **토큰 확인** — 색/타이포/간격이 어떤 변수(토큰)인지 확인하고 프로젝트 토큰과 매핑(D3). 매핑 대상이 없으면 §8.
4. **자산 추출** — 아이콘·이미지는 `download_figma_images`로 내려받아 사용(벡터=SVG). 스크린샷을 잘라 쓰지 않는다.
5. **응답 크기 관리** — node 데이터가 크면 대상 nodeId로 범위를 좁혀 조회한다(전체 파일 무분별 조회 금지).

## 6. 구현 절차 (5단계)

1. **매핑 확정**: 대상 화면/컴포넌트 ↔ 화면설계서 화면ID ↔ Figma node-id를 확인한다(화면ID 체계 [TBD] — 미확정 시 화면명으로 기록).
2. **토큰·컴포넌트 매핑**: 색/타이포/간격→디자인 토큰, 배리언트→`shared/ui`. 신규 필요 시 디자인시스템 정의를 그대로 컴포넌트화.
3. **레이아웃 재현**: Figma 오토레이아웃(방향·gap·padding·정렬·sizing)을 그대로 flex/grid로 옮긴다. 반응형은 **디자인에 정의된 뷰포트만**(대응 뷰포트 [TBD]).
4. **상태 구현**: 디자인에 정의된 상태만 구현(예: Button Default/Hover/Active/Disabled). 없는 상태 임의 추가 금지.
5. **검증**: 구현 스크린샷 vs Figma 스크린샷 시각 대조 + 토큰 사용 여부 점검(하드코딩 0) + 출처 node-id 주석 확인.

## 7. 금지 사항 (임의 처리 금지)

- 임의 색/폰트/폰트웨이트/간격/radius/그림자 값 사용 또는 "비슷하게" 근사
- 디자인에 없는 컴포넌트·섹션·아이콘·문구(카피) 추가·삭제·치환
- 레이아웃 임의 재배치·정렬 변경·요소 크기 임의 조정
- 임의 애니메이션·트랜지션·hover 효과 추가(디자인/모션 스펙에 있을 때만)
- 데이터가 없는 영역을 임의 더미 계측값·차트로 채우기(빈 상태는 디자인의 빈 상태를 따름)
- 상태 등급 색·라벨을 디자인과 다르게 임의 지정(등급 체계 자체가 미확정 → `docs/requirements/source-inconsistencies.md`)
- 배경 투명 처리(불투명 원칙, frontend.rule.md R12 — 사용자 명시 지시 시 예외)
- 접근성 속성(라벨/역할) 누락(디자인 텍스트·의미를 그대로 반영)

---

## 8. 불명확·괴리 처리

디자인에 값이 없거나(누락), node 데이터와 스크린샷이 모순되거나, 대응 토큰/컴포넌트가 없을 때:
1. **임의로 결정하지 않는다(D6).**
2. 무엇이 불명확한지 node-id와 함께 **사용자에게 확인 요청**한다.
3. 확정 전까지 해당 부분은 구현을 보류하거나, 합의된 임시 처리를 **명시적으로 표기**한다(추측성 완성 금지).
4. 디자인시스템에 반영이 필요한 신규 토큰/컴포넌트는 디자인시스템 색인 문서(§2, [TBD])에 등록 후 사용한다.

## 9. 체크리스트 (구현 PR 전)

- [ ] 모든 색/타이포/간격/radius가 **디자인 토큰**으로 표현됨(하드코딩 0)
- [ ] 타이포 스케일을 디자인시스템 정의대로 사용
- [ ] 공용 컴포넌트(`shared/ui`) 재사용, 배리언트/상태가 디자인과 일치
- [ ] 오토레이아웃(gap/padding/정렬/sizing) 그대로 반영, 정의된 뷰포트만 대응
- [ ] 아이콘/이미지는 Figma에서 추출한 자산 사용(스크린샷 크롭 아님)
- [ ] 출처 node-id 주석/PR 기재(추적성)
- [ ] Figma 스크린샷과 구현 시각 대조 완료, 임의 추가/변경 없음
