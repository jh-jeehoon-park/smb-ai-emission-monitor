## 2. 목적과 범위

산출물 xlsx 3종(**요구사항정의서 · 화면설계서 · 데이터 정의서**)과 그 원천 마크다운을 쓸 때 따르는 규칙이다.

- **트리거**: "xlsx 3종 작성·갱신" 작업을 할 때. 화면 구현이나 코드 작업에는 적용하지 않는다.
- **적용 대상**: `docs/specs/**` 의 마크다운, `docs/specs/*.xlsx` 3종, 생성 스크립트.
- 이 문서는 **`docs/specs/README.md`를 대체하지 않는다.** README가 이미 정한 것(근거 표기 규약 §3, ID 체계 §4, 컬럼 대응 §5.1, 화면 문서 템플릿 §9)은 그대로 두고, **xlsx 산출물이 지켜야 할 완전성과 산출 방식**만 여기서 정한다.

### 2.1 마크다운과 xlsx의 역할이 다르다

| | 무엇 | 읽는 사람 |
|---|---|---|
| `docs/specs/**.md` | **개발자 확인용.** 근거의 원천, 기각한 대안, 코드 경로까지 | 우리 |
| `docs/specs/*.xlsx` | **발표본.** 최종 심사가 이것으로 이루어진다 | 발주처·심사자 |

`[사용자 지시 2026-08-20]`

이 구분이 X8을 낳는다 — **마크다운을 봐야만 알 수 있는 내용을 남기면 심사자는 그것을 볼 수 없다.** xlsx는 마크다운을 가리키는 색인이 아니라 자립한 문서여야 한다.

### 2.2 왜 규칙이 먼저인가

이 산출물은 **심사 대상**이다. 화면에 무엇이 왜 있는지를 행 단위로 설명해야 하고, 설명할 수 없는 행이 하나라도 있으면 문서 전체의 신뢰가 깎인다. 규칙 없이 쓰면 320행 중 어느 행이 근거를 가졌는지 사람이 셀 수 없다.

## 3. 절대 규칙 (X1~X8)

위반 시 즉시 멈춰 사용자에게 보고한다.

| # | 규칙 |
|---|------|
| **X1** | **근거 없는 행을 쓰지 않는다.** 모든 데이터 행에 §4의 태그가 하나 이상 붙는다. 태그가 없으면 그 행은 xlsx에 넣지 않는다 |
| **X2** | **원문이 정하지 않은 것을 정한 것처럼 쓰지 않는다.** 미확정은 `[TBD-nn]`·`[PROVISIONAL]`로 드러내고, 빈 칸은 빈 칸으로 둔다. 그럴듯한 값으로 채우지 않는다 |
| **X3** | **미구현을 구현한 것처럼 쓰지 않는다.** 없는 화면·없는 기능·없는 필드를 지어내지 않는다. 구현 상태는 `requirements.md` §3 추적표가 정본이다 |
| **X4** | **항목 단위 완전성.** 화면설계서는 영역이 아니라 **영역 안의 항목**을 행으로 쓴다(§6). 화면에 보이는 것 중 행이 없는 것이 있으면 결함이다 |
| **X5** | **타 프로젝트 잔재를 남기지 않는다.** 양식에 딸려 온 예시행과 우리 체계에 없는 ID 접두사(`ZB-*`, `REQ-US-*`, `REQ-GU-*`, `REQ-EM-*`, `SCR-EM-*`)는 전량 삭제한다 |
| **X6** | **xlsx를 손으로 고치지 않는다.** 원천은 마크다운이고 xlsx는 생성물이다. 엑셀에서 직접 고치면 다음 생성 때 사라진다 |
| **X7** | **없는 역할을 문서에 남기지 않는다.** 역할은 `관리자 / 운영자 / 게스트` 셋뿐이다. `비로그인`·`시민`은 이 시스템에 없다 `[사용자 확인 2026-08-20]` |
| **X8** | **xlsx가 자립해야 한다.** 발표는 xlsx로 이루어진다 `[사용자 지시 2026-08-20]`. 마크다운을 열어야만 알 수 있는 내용을 남기지 않는다 — 근거·이유·미정 사항을 **셀 안에 글로** 넣는다. `"상세는 screens/SCR-OP-003.md 참조"` 같은 칸은 금지다 |

> **X8과 X1은 함께 읽는다.** X1이 모든 행에 근거를 요구하는데 화면설계서에는 **근거를 담을 열이 없었다**(14열 중 없음). 그래서 §5.2에서 `근거`·`비고` 열을 추가한다 — 열이 없으면 X1을 지킬 방법이 없다.
>
> **X5의 근거는 실제로 밟은 함정이다.** 커밋 `2c0c07e`가 기록해 두었고, `v0.1`에는 지금도 잔재가 살아 있다 — 화면설계서 세 시트의 `ZB-U-AUTH-01 로그인/회원가입`, 요구사항정의서의 `REQ-GU-001 청약 공고 목록`·`REQ-US-001 청약 신청 안내`·`ZB-U-SUBS-03`, 데이터 정의서의 `REQ-EM-001 / SCR-EM-001 / 배출량 정보`(비고 `작성 예시`).

## 4. 근거의 위계

`docs/applications/`에 원천 문서가 3개 있고, **주요 문서는 앞의 둘**이다 `[사용자 지시 2026-08-20]`.

| 순위 | 원천 | 태그 | 쓸 때 |
|---|---|---|---|
| **1** | 사업계획서(121쪽) · 발표자료(52쪽) | `[원문 p.nn]` · `[원문 발표 p.nn]` | 그대로 있는 값. 최우선 |
| **2** | 공정자료(20쪽) · 데이터셋 | `[공정자료 p.nn]` · `[데이터셋 경로]` | **원문이 아님을 명시.** 원문을 보완할 때만 |
| **3** | 회의 · 사용자 · 우리 결정 | `[회의 …]` · `[사용자 …]` · `[설계: 이유]` | **이유를 함께 적는다** |
| **4** | 계산·임시값·미정 | `[파생: 식]` · `[PROVISIONAL]` · `[TBD-nn]` · `[INC-nn]` | 교체 지점을 명시 |

**2순위를 남기는 이유**: pH 배출허용기준 5.8~8.6은 `[공정자료 p.11]`이 유일한 출처다. 근거를 두 원문으로만 한정하면 이미 화면에 있는 값이 근거를 잃는다. 다만 2순위는 **원문이 아니라는 사실을 행에 적는다.**

### 4.1 태그 15종

README §3이 정한 9종에 **`[사용자 …]` 5종을 정식 등록**한다. 이 5종은 `docs/specs/` 전체에서 43회 실사용되는데 §3 표에 없었다.

| 태그 | 뜻 |
|---|---|
| `[원문 p.nn]` | 사업계획서에 그대로 있는 값. 여러 쪽은 `·`로 이음 |
| `[원문 발표 p.nn]` | 발표자료. **`[발표 p.nn]`으로 줄이지 않는다** |
| `[공정자료 p.nn]` | 주관사 공정 설명 자료 — 원문이 아니다 |
| `[데이터셋 경로]` | HSK 제공 실측 샘플 — 원문이 아니다 |
| `[파생: 식]` | 원문 값이나 계측에서 계산한 값 |
| `[PROVISIONAL]` | 원문에 없어 임시로 정한 값. 실체는 `src/shared/config/provisional.ts` |
| `[TBD-nn]` | 원문이 정하지 않음 |
| `[INC-nn]` | 원문끼리 어긋남. 채택안과 이유를 함께 |
| `[설계]` | 우리 결정. **이유와 기각한 대안을 함께** |
| `[회의 YYYY-MM-DD]` | 사업신청서 밖에서 정해진 것 |
| `[사용자 지시 YYYY-MM-DD]` | 사용자가 지시한 작업 방향 |
| `[사용자 결정 YYYY-MM-DD]` | 선택지를 사용자가 고른 것 |
| `[사용자 확인 YYYY-MM-DD]` | 사용자가 사실로 확인해 준 것 |
| `[사용자 요청 YYYY-MM-DD]` | 사용자가 요청한 화면·기능 |
| `[사용자 지적 YYYY-MM-DD]` | 사용자가 잡아 준 결함 |

`[TBD-nn]`·`[INC-nn]`은 `docs/requirements/source-inconsistencies.md`에 **등록된 번호만** 쓴다. 번호를 붙이기 전에 그 항목의 등록 내용을 읽는다.

### 4.2 사용자 요청도 같은 기준이다

사용자가 별도로 요청한 것은 `[사용자 요청 …]` 태그를 달고, **왜 요청됐는지를 함께 적는다** `[사용자 지시 2026-08-20]`. "사용자가 원해서"는 근거가 아니다 — 무엇을 해결하려는 요청이었는지가 근거다.

```
좋음:  잔여 수명 추이 그래프 | [사용자 요청 2026-08-19] 원문 발표 p.18 그림의 RUL 예측 그래프가 화면에 없었다
나쁨:  잔여 수명 추이 그래프 | [사용자 요청]
```

### 4.3 지어내지 않는 둘

README §3.1이 이미 못박은 것을 잇는다. 이 둘은 **어떤 태그를 붙여서도** 쓰지 않는다.

| 항목 | 이유 |
|---|---|
| 배출허용기준 등 **법정 판정값** | 법령이 원천이다. 우리가 정하면 그냥 틀린 값이 된다 |
| 설비 제어의 **안전 인터록** | 없으면 위험한 동작을 만든다. 시연이라도 마찬가지다 |

| 6 | `단위` | `단위` 열 |
| 7 | `계산식/로직` | `계산식/로직` 열 (`[파생: …]` 내용) |
| 8 | `수집 출처/레퍼런스` | `출처·근거` 열 **전체**(태그 포함) |

| 11 | `비고` | `[TBD]`·`[PROVISIONAL]` 사유 |

### 5.5 마크다운에 원천이 없는 열

네 열(`구분` · `변경구분` · `변경근거` · `수용여부` · `데이터 그룹`)은 마크다운에 대응 열이 없다. **지어내지 않고 아래 규칙으로 채운다.**

| 열 | 채움 규칙 |
|---|---|
| `구분(기능/비기능)` | 시트로 정해진다 — `비기능요구사항` 시트는 `비기능`, 나머지는 `기능` |
| `변경구분` | 첫 작성은 `추가`. 이후 판본은 이전 xlsx와 대조해 `수정`/`삭제` |
| `변경근거` | 첫 작성은 `신규 작성`. 이후는 **무엇이 왜 바뀌었는지** 한 문장 |
| `수용여부` | `requirements.md` `수용` 열이 있으면 그 값. 없으면 구현 상태로 — `구현`·`부분`은 `Y`, `미구현`은 `Y`(수용했으나 미착수), `대상아님`은 `N` |
| `데이터 그룹` | `data-definition.md`의 **절 제목**(엔티티명). 예: `§7 설비 (Equipment)` → `설비` |

### 5.6 마크다운 절 → xlsx 목적지 (X8)

**모든 절에 목적지가 있어야 한다.** 목적지가 없는 절은 심사자가 볼 수 없다.

| 화면 문서 절 | xlsx 목적지 |
|---|---|
| §2 화면 개요 | 역할 시트 `화면 ID`~`설명`, `관리자`~`게스트` |
| §3 화면 구성 | 역할 시트 `구성요소`·`형태` (화면 요약행) |
| **§3.1 항목 목록**(신설) | 역할 시트 **항목 행** + `부록. 항목 목록` 시트 |
| §4 요구 데이터 | 데이터 정의서 |
| §5 상호작용 | 역할 시트 `SUBMIT`·`CANCEL`·`After Action` |
| §6 상태와 예외 | 역할 시트 `비고` — 빈 상태·통신두절·결측 처리를 글로 |
| **§7 설계 근거** | **`부록. 설계 근거` 시트**(신설) — 화면ID별로 왜 이 구성인가·기각한 대안 |
| **§8 미정·제약** | 역할 시트 `비고` + `부록. 설계 근거` 시트 |

`부록. 항목 목록` 시트의 열: `항목ID · 집합 · 라벨 · 기호 · 단위 · 표시 자릿수 · 근거 · 쓰이는 화면`.
`부록. 설계 근거` 시트의 열: `화면 ID · 구분(근거/미정) · 내용 · 근거 태그`.

> `부록. 화면 구성요소 목록`(기존)은 **구성요소 통제 어휘**용이고 `부록. 항목 목록`은 **도메인 항목**용이다. 축이 달라 합치지 않는다 — 합치면 `입력 폼`과 `pH`가 같은 표에 들어간다.

## 6. 항목 단위 완전성 (X4)

### 6.1 무엇이 '한 행'인가

**영역이 아니라 영역 안의 항목이 한 행이다** `[사용자 지시 2026-08-20]`.

`시계열 변화 > 수질·설비 시계열`을 예로 든다. 이 패널 하나를 한 행으로 쓰면 안 되고, 그 안의 항목 각각이 행이 된다.

```
잘못:  SCR-OP-003 | 수질·설비 시계열 | 소형 다중 차트
맞음:  SCR-OP-003 | pH   | 소형 다중 차트 + 현재값 + 기준 5.80–8.60 · 초과 N건
       SCR-OP-003 | DO   | 소형 다중 차트 + 현재값 + 기준값 미확정 [TBD-45]
       SCR-OP-003 | EC   | 소형 다중 차트 + 현재값
       … (수질 8종 + 설비 3종)
```

**세는 기준**: 사용자가 화면에서 읽는 값·라벨·상태가 하나라도 있으면 행이 된다. 반복되는 최소 단위 1개 = 1행. 배지·칩·범례도 포함한다.

**세지 않는 것**: 여백·구분선·아이콘 장식처럼 사용자가 읽을 내용이 없는 것.

### 6.2 두 층으로 나눈다

같은 항목이 여러 화면에 나온다 — 설비 4대는 8군데, 계측 11항목은 3군데, XAI 기여 5항목은 3군데. 화면마다 근거를 다시 쓰면 320곳에서 갈린다.

| 층 | 어디 | 한 행이 무엇인가 | xlsx 목적지 |
|---|---|---|---|
| **항목 사전** | `docs/specs/items.md` | 항목 1개. `항목ID · 집합 · 라벨 · 기호 · 단위 · 자릿수 · 근거 · 단일 출처(코드 경로)` | 화면설계서 **`부록. 항목 목록`** |
| **화면×항목** | `screens/<ID>.md` **§3.1** | 그 화면에서의 그 항목. `항목ID · 영역 · 구성요소 · 형태` | 화면설계서 역할 시트 |

**마크다운에서는 근거를 항목 사전에 한 번만 쓰고 화면 문서는 항목ID로 참조한다.** E1(단위·자릿수를 한 곳에 모은다)이 이미 쓰는 원리와 같다.

**그러나 xlsx에서는 생성기가 그 참조를 글로 펼친다**(X8). 심사자는 `항목ID`만 적힌 칸을 보고 뜻을 알 수 없다 — 역할 시트의 `근거` 열에는 항목 사전의 근거와 그 화면에서의 이유가 **함께 문장으로** 들어간다. 마크다운의 중복 제거와 xlsx의 자립은 서로 어긋나지 않는다. 펼치는 일을 생성기가 하기 때문이다.

역할 시트의 `#` 열은 화면 요약행이 `n.0`, 항목 행이 `n.1`·`n.2`…를 쓴다. 화면 하나가 여러 행을 차지하고 `화면 ID`는 반복된다.

> **`screens.md` §7에 얹지 않는 이유** — §7은 `구성요소·형태`의 통제 어휘(공용 UI·위젯·셸)이고 항목은 도메인 값이라 축이 다르다. 섞으면 `StatusBadge`와 `pH`가 같은 표에 들어간다.

### 6.3 확정된 집합과 미확정 집합을 가른다

**항목 집합이 원문으로 확정된 것과 시연값인 것은 쓰는 방법이 다르다.** 이 구분이 없으면 시연 fixture의 개수를 명세처럼 적어 X2를 어긴다.

| 부류 | 어떻게 쓰는가 | 예 |
|---|---|---|
| **원문이 목록을 확정** | **항목마다 한 행.** 그 목록이 곧 명세다 | 계측 11항목 `[원문 p.55]` · 등급 4 `[원문 발표 p.15]` · 우선순위 3 `[원문 p.32]` · 법정 점검 5 `[공정자료 p.5·19]` · 사업장 10개소 `[원문 p.29]` |
| **종류만 있고 개수는 미정** | **"1대당 한 행" 반복 규칙**을 쓴다. 개수를 명세로 적지 않고 시연값은 **예시**로 표기 + `[PROVISIONAL]` | **설비** — 원문은 펌프·폭기장치·약품주입펌프라는 종류만 정한다 `[원문 p.30·62·63]`. 대수는 어디에도 없다 `[TBD-48]` |

> **실제로 걸린 사례다.** 시연 fixture는 전 사업장 동일하게 설비 4대(`EQUIPMENT_TEMPLATE`)를 돌려주는데, 그 `4`에 원문 근거가 없다. `EQ-01`~`EQ-04`를 명세 행으로 적으면 실증 사업장이 3대나 6대일 때 문서가 틀린 값이 된다. **사업장별로 다른지 같은지도 원문이 말하지 않는다** — 다르다고 적는 것도 추측이다.

## 7. 원천과 생성

### 7.1 원천은 마크다운이다

```
docs/specs/*.md  ──(생성 스크립트)──▶  docs/specs/*.xlsx
```

xlsx는 생성물이다(X6). `.gitattributes`가 `*.xlsx binary`로 잡아 **diff가 나오지 않으므로**, 무엇이 바뀌었는지는 마크다운의 변경 이력이 유일한 기록이다.

### 7.2 기존 파일의 셀만 교체한다

`v0.1`에는 발주처 양식의 서식·시트 구성·인쇄 설정이 들어 있다(요구사항정의서 539KB). **통째로 새로 만들면 그 서식을 잃는다** `[사용자 결정 2026-08-20]`.

| 규칙 |
|---|
| `openpyxl`로 기존 파일을 열어 **데이터 행만** 지우고 다시 채운다 |
| `표지`·`변경이력` 시트와 헤더 행·병합·열폭·인쇄 설정은 건드리지 않는다 |
| 헤더 행은 **문자열로 찾는다.** 행 번호를 가정하지 않는다 — 요구사항정의서는 시트마다 헤더 행이 3행/4행으로 다르다 |
| 실행 전 `.bak` 사본을 만든다. `.gitignore`가 `*.xlsx.bak`를 이미 제외한다 |
| **빈 양식 사본을 따로 보관한다** — 데이터가 들어간 파일이 손상되면 서식을 되찾을 곳이 필요하다 |

생성기는 `scripts/build-xlsx.py`에 둔다. Node 쪽에는 xlsx 라이브러리가 없고 `openpyxl 3.1.5`가 환경에 있다.

### 7.3 버전

**`v0.1`은 "문서 작업이 완성된 상태"를 뜻한다** `[사용자 확인 2026-08-20]`. 지금 파일에 붙은 `v0.1`은 아직 그 상태가 아니다 — 발주처 양식에 타 프로젝트 잔재가 남은 껍데기다.

| 규칙 |
|---|
| 작업이 끝날 때까지 **파일명과 `변경이력` 시트의 버전을 `v0.1`로 유지**한다. 중간 판본마다 번호를 올리지 않는다 |
| 같은 파일을 **덮어쓴다.** 새 파일을 만들지 않는다 |
| `변경이력` 시트의 `작성일자`는 생성할 때마다 갱신한다 |
| 완성 후 내용이 바뀌면 그때 `v0.2`로 올린다 |

마크다운은 이와 별개로 Semantic Versioning을 따른다(`document-template.rule.md`).

## 8. 자기 검사

`npm run verify:docs`(`scripts/verify-docs.mjs`)에 아래 검사를 추가한다. 총 개수는 `results.length`로 자동 계산되므로 `check()`만 더하면 된다.

| 검사 | 무엇을 잡는가 |
|---|---|
| 근거 태그 누락 | 화면 문서 §3.1·§4, `data-definition.md`, `items.md`의 데이터 행에 §4 태그가 하나도 없는 행 |
| 표 헤더 통일 | §10의 헤더 불일치 — 정해진 헤더 문구를 벗어난 표 |
| 항목 단위 완전성 | §6.3 상수의 원소 수 = `items.md` 행 수 = 화면 문서 §3.1 참조 수 |
| 잔재 ID | `ZB-`·`REQ-US-`·`REQ-GU-`·`REQ-EM-`·`SCR-EM-` 접두사가 마크다운에 남아 있는지 (X5) |
| 마크다운 참조 셀 | xlsx 셀에 `.md`·`참조`·`상세는`처럼 **문서를 가리키는 문구**가 있는지 (X8) |

> **`walk(dir, ext)`의 기본 확장자는 `.md`다.** 소스를 보는 검사는 `ext`를 반드시 넘긴다 — 빠뜨리면 파일을 한 건도 읽지 않고 **조용히 통과한다**. 실제로 그렇게 통과한 적이 있다.
>
> 검사를 추가하면 **일부러 깨뜨려 실패를 확인한다.** 통과만 보고 넘기면 검사가 있다고 착각한 채 남는다.

### 8.1 검사가 잡지 못하는 것

| 기계가 보는 것 | 사람이 봐야 하는 것 |
|---|---|
| 태그가 붙어 있는가 | **그 태그가 맞는 근거인가** — 원문 그 쪽을 열어야 안다 |
| 헤더 문구가 같은가 | 그 열에 맞는 값이 들어갔는가 |
| 행 수가 상수와 맞는가 | 화면에 실제로 그렇게 보이는가 |

통과는 "형식이 어긋나지 않았다"는 뜻이지 "근거가 맞다"는 뜻이 아니다.

## 9. 작성 절차 — 화면 한 개

1. **원문을 먼저 읽는다.** 그 화면 주제 쪽의 **이미지까지** 판독한다. `source-inconsistencies.md` §5.4 판독 대장에서 그 쪽 상태를 확인한다 — `미판독`인 쪽을 근거로 "원문에 없다"를 적지 않는다
2. `screens/<ID>.md` §3의 영역 목록을 확인한다
3. 영역마다 **항목을 §6.3 상수에서 가져온다.** 손으로 세지 않는다
4. 항목이 `items.md`에 없으면 먼저 등록한다(근거 포함)
5. `screens/<ID>.md` **§3.1**에 화면×항목 행을 쓴다 — 항목ID 참조 + 그 화면에서의 형태
6. `data-definition.md`에 그 화면이 새로 쓰는 필드가 있으면 추가한다
7. `requirements.md` 해당 FR 행의 화면·상태를 갱신한다
8. 새 추정을 도입했으면 `assumptions.md` §3에 근거·위험도·철회 조건을 쓴다
9. `npm run verify:docs`
10. 생성 스크립트로 xlsx를 다시 만든다. **엑셀에서 직접 고치지 않는다**(X6)
11. **xlsx만 열어 읽어 본다.** 마크다운을 봐야 알 수 있는 칸이 있으면 그 칸을 글로 채운다(X8)
