## 2. 개요 & 적용 범위

본 저장소 **모든 코드**의 주석 작성 기준이다. `frontend.rule.md`(R18)의 "기본 무주석, WHY만" 원칙을 구체화한다.

- 적용: 웹 대시보드 소스 `src/**/*.{ts,tsx,js,jsx}`. 다른 영역(백엔드·Edge) 코드가 본 저장소에 추가되면 동일 원칙을 적용한다.
- 원칙 충돌 시 우선순위는 `frontend.rule.md` §5(사용자 지시 → 절대규칙 → 로컬 규칙 → 컨벤션)를 따른다.

---

## 3. 핵심 원칙

- **코드가 곧 설명이다:** 주석이 필요하면 먼저 변수·함수 이름을 더 직관적으로 바꾼다.
- **'왜(Why)'만 남긴다:** '무엇(What)'은 코드가 이미 보여준다. 그렇게 작성한 **이유·맥락**만 전한다.
- **가장 쉬운 언어로:** 누구나 즉시 이해할 단어를 쓴다.
- **군더더기 제거:** 한 줄이라도 줄일 수 있으면 줄인다.

## 4. 절대로 쓰지 않는 주석 (Forbidden)

### 4.1 코드를 그대로 읽어주는 주석
```typescript
// BAD
const user = await fetchUser(userId); // 유저 정보를 가져옵니다.
if (!isLoggedIn) return; // 로그인되어 있지 않으면 종료합니다.
```

### 4.2 설명조의 사족(서술형)
```typescript
// BAD
// 에러가 발생하는 것을 방지하기 위해 예외 처리를 추가해 두었습니다.
```

### 4.3 Git이 아는 정보(작성자·날짜·이력)
```typescript
// BAD
/**
 * 작성자: 개발자
 * 내용: 결제 연동 로직 수정
 */
```

### 4.4 주석으로 숨겨둔 코드(Dead Code)
안 쓰는 코드는 주석 처리하지 말고 **삭제**한다. 복구는 Git으로 한다.

---

## 5. 작성해야 하는 주석 (Allowed)

오직 **비직관적 이유**·**숨겨진 맥락**을 전할 때만 쓴다.

### 5.1 비즈니스 맥락 및 정책 제약
```typescript
// GOOD
// 통신 두절 구간은 결측으로 표시한다. 0으로 그리면 배출량 급감으로 오독된다.
```

### 5.2 버그 회피·우회 로직(Workaround)
```typescript
// GOOD
// iOS Safari 스크롤 튐 방지를 위해 repaint를 강제로 유도한다.
```

### 5.3 불변식·제약(Invariant)
```typescript
// GOOD
// anomalyScore 는 항상 0~100 (서버 산출 범위). 범위 밖 값은 수집 파이프라인 버그.
```

### 5.4 출처 추적 주석(디자인/계약)
`figma-implementation.rule.md`(D5)에 따른 **Figma node-id 출처 주석**은 허용한다(추적성). 계약 참조도 동일.
```typescript
// GOOD
// figma 20:183 Card/Product
```

## 6. TODO / FIXME

- 임시 조치·미완은 `// TODO(담당/이슈): 내용` · `// FIXME(사유): 내용` 형식으로 남기고, 근거(이슈/티켓)를 함께 적는다.
- 단, **실 API 연동 시 Mock·임시 폴백은 같은 PR에서 전량 제거**한다(`frontend.rule.md` A1). TODO로 방치 금지.

## 7. 공개 API 문서화(선택)

- slice Public API(`index.ts`)와 `shared/`의 **export 되는 컴포넌트/함수/타입**은 필요 시 **간결한 TSDoc 한두 줄**(용도·제약)만 허용한다. 내부 구현 주석은 §4/§5 원칙을 그대로 따른다.
- 타입으로 표현 가능한 것은 주석 대신 **타입**으로 드러낸다.

---

## 8. 실행 규칙 (Claude)

1. **기본값은 '주석 없음(Zero Comments)'.** §5의 명확한 이유가 없으면 한 줄도 쓰지 않는다.
2. **출력 전 검토:** 코드 제출 전, 자명하거나 불필요한 주석이 남아있지 않은지 확인하고 모두 제거한다.
